# infiltrator-profile-store

> 层级：L3

CORE-018.3 的 owner：实现 engine-neutral `ProfileStore` 持久化，包括 engine namespace、原始 `ProfileDocument` 与 sidecar、workspace lease、revision CAS、active-profile reference 和恢复事务。当前 crate 已接管 engine-scoped `EngineProfileStore` 状态、安全 document path、durable document/backup/sidecar I/O、文档删除及 sidecar 删除失败后的精确回滚、document validation、workspace coherent read/source/protection projection 与成对发布、profile catalog 与 aggregation-template sidecar、共享写锁、profile namespace schema/bootstrap 与 durable TOML backup recovery、profile-state 元数据、订阅凭证映射及 active-reference/owner-proof durable record I/O、schema validation、owner-proof v1 migration 和 durability-error readback reconciliation。

完整 production `ProfileStore` / `ActiveProfileReferenceStore` port adapter、selection reader、workspace transaction lease 与跨文件 reset/workspace transactions 仍由 `mihomo-config::ConfigManager` 暴露或协调；owner-switch entry/recovery orchestration 已迁入共享 coordinator。本 crate 已接管 selection-to-owner-binding lease、secure owner-token generation、live Core owner lease 的 managed start proof 与 exact terminal release、外部终态证据后的 owner record recovery、owner normalization、product-root/owner-state/admission locks、进程内 typed owner registry、active-reference/owner-proof typed record I/O、schema migration、durability reconciliation、revision CAS authorization/target-evidence and next-state policy、owner-switch entry/recovery 与 typed stage leases、workspace 文件协议。进程内 registry 将 owner token、`Bound`/`Binding`/`Switching` 状态与 owner admission guard 绑定；绑定、切换、取消和候选 finalize 都通过校验前置状态的命名迁移执行，不提供任意状态赋值。registry 只协调单个 owner 进程，不替代跨进程文件锁或宿主 IPC。engine-scoped schema/bootstrap、TOML 原子读写和版本化 legacy file/state/credential migration 都归共享 owner；Mihomo facade 只注入 `LegacyV1` 的旧 settings、sync index 与目录规格。两个 engine 的 production `ProfileStore` 组合尚未迁入共享 adapter。store 不解析 Mihomo YAML 或 sing-box JSON，原生格式与 native check 由对应 config adapter 持有。

可移植 profile 名称由 `infiltrator-domain::profiles` 统一校验，文件路径、sidecar 与远端旧格式迁移共用同一规则；Mihomo 私有的重复校验和消毒入口已退役。
