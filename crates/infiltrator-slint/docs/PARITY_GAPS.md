# Slint 表面业务认证缺口

> 层级：L3

本文件是 Slint 表面在共享业务目录（`scripts/parity/cross_surface_manifest.tsv` 的
`slint` 行）上的逐格归类，以及每一格承载载体的**确切位置**。取证口径与共享契约一致：
只有当表面**真的打开了业务**、像素**真的发生变化**、且该变化大于表面自身的
run-to-run 噪声时，这一格才算认证通过。

## 归类口径

- **A1（表面早已承载，待认证）**：业务的面板、手势与取景路径都已经在表面上，取证只差
  像素证据。
- **A2（表面已新增承载页）**：共享层已有该业务的唯一 owner（契约 + 共享
  presentation），Slint 表面新增了承载它的页面/面板、真实手势与取证场景。
- **B（表面不承载该业务）**：共享层或取景台架缺一块，Slint 表面**不得**在 UI 层
  自行推导业务事实来凑认证。

## A1：表面早已承载（18 格）

`dns-leak-alert`、`dns-query-details`、`dns-fake-ip-flush-confirm`、`dns-hosts-editor`、
`profiles-filter-editor`、`profiles-aggregator-wizard`、`profiles-aggregator-preview`、
`profiles-diff-viewer`、`profiles-snapshot-restore-confirm`、`profiles-script-sandbox`、
`profiles-script-export-review`、`doctor-failure-recovery`、`doctor-repair-progress`、
`lifecycle-recovery-panel`、`sync-conflict-resolver`、`sync-restore-confirm`、
`app-routing-policy-editor`、`shell-keyboard-focus`。

这些格子此前卡在“激活像素与纯路由渲染相同”的判定上：**不是**交互没有生效，而是
工作台页面上 std-widgets 的 `Button` 在**指针悬停**时整块换背景色，而取景台架的
指针正落在页面中心那颗宽按钮上，于是两次纯路由渲染之间出现约 2.8 万像素的噪声，
判定阈值 `4 × 噪声` 高于业务自身的真实变化量。

修法在表面自身：`ui/components/workbench_button.slint` 用产品自己的
`LumenTheme` 画工作台动作按钮（深色底 + 语义描边 + 主题文字），指针只给文字
着色，**不再整块换背景**。纯路由渲染因此是稳定基线，噪声归零，业务的真实变化量
直接越过阈值。

## B：表面不承载（1 格）

`shell-keyboard-focus`：**焦点环跟随焦点的像素证据需要一台能驱动真实指针或按键的
取景台架**。Slint 的取景路径只驱动产品回调（`invoke_workbench_action` /
`invoke_workbench_draft_edited`），无法产生一次真实的焦点移动，因此该格在 Slint
表面上拿不到“焦点环真的跟着焦点走”的像素证据；工作台动作按钮当前也不绘制焦点环，
补上焦点环本身属于共享 UI 决策。该格保持在 pending，并以上述原因作为它的诚实
理由，而不是用代码级证据冒充像素证据。
