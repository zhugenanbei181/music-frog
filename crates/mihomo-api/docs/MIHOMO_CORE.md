# Mihomo adapter 约束

> 层级：L3

本页只记录 Mihomo 特有规则；crate 职责见 [README.md](../README.md)。

- `mihomo-api` 封装 REST/WebSocket、wire DTO、鉴权与错误映射；这些类型不得进入共享业务或 UI。
- 运行中 Fake-IP 清理通过 scoped `ControllerFakeIpCachePort` 调用 Mihomo controller。两个锁定 Mihomo 版本都接受 `POST /cache/fakeip/flush` 并返回 `204`（[官方 API 文档](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md)）；typed adapter receipt 绑定请求 scope/operation，但 controller 不提供缓存内容读回，因此该证据不声称读回证明缓存为空。adapter nextest：v1.19.32 `f03b17e0-1ed2-4700-b35a-617c41b2036c`；v1.19.18 `ce963eae-46ab-4d85-9e75-cc260dfbfb18`；non-UI Core unified nextest `3be9dc89-9b76-4aa8-abcd-30504c61f52b`（3209 passed、8 skipped）。`fake_ip_cache.flush` evidence 只授权 Linux amd64、revision 1 与这两个精确版本。
- v1.19.18 与 v1.19.32 的 real-process smoke 使用本地 HTTP rule-provider fixture 验证 typed `RuntimeGateway` list/update/readback：初始 `ruleCount=1`，`UpdateRule` 后读回 `ruleCount=2`。Mihomo wire `vehicleType`、`ruleCount` 的 camelCase 映射与远程 provider 缺失/null payload 由 adapter 单测和 live list 验证；HTTP provider 的 payload 仍返回 `None`，不伪造内联规则。官方 `PUT /providers/rules/:name` 返回 HTTP 204（[官方 API 文档](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md)）。adapter nextest：v1.19.32 `ce8e3858-508c-43ac-be3d-87d5a4d74925`；v1.19.18 `47ce3a57-c6d1-4042-8b31-0d24c4faed32`；wire DTO nextest `27a14c80-c7b8-4a20-9cd8-da542200abbb`；non-UI Core unified nextest `ca741c0f-4f37-4c8a-ba3f-63f4cf3b2f83`（3212 passed、8 skipped）。`provider.list_rule` 与 `provider.update_rule` 只授权锁定 Linux amd64、revision 1 与这两个精确版本；proxy-provider operations 仍保持 Unsupported。
- `mihomo-config` 负责 Mihomo YAML 的解析、校验和持久化；校验失败不得发布配置。
- Mihomo 进程归 `mihomo-process`，版本安装归 `mihomo-version`，共享 OS/host 能力归 `infiltrator-platform`；controller 可用不代表代理/VPN 已生效。
- 凭据不进入日志、普通错误或 UI；流式请求须支持取消、断线处理与有界缓存。
- 产品发行资产版本和摘要只以 [`mihomo-assets.json`](../../../packaging/mihomo-assets.json) 为准；逐操作兼容证据另以 [`mihomo-evidence-assets.json`](../../../packaging/mihomo-evidence-assets.json) 锁定，不能改变发行版本。
- capability provider 启动时校验 [`adapter-operation-declarations.json`](../adapter-operation-declarations.json) 覆盖完整 operation catalogue，并将 Supported evidence ID 与 target-scoped schema v2 evidence asset 锁对应。证据须匹配精确 Core version、完整 Rust `binary_target` triple 与 `adapter_revision`；这些字段也进入 `CoreCapabilityScope`，使跨构建目标或 revision 的结果不能复用。当前 evidence lock 只有 `x86_64-unknown-linux-gnu`、revision 1；Android/iOS/其他 target triple 和 revision 均 `HostUnavailable`，version-bound operation 的版本或 operation evidence 缺失为 `VersionUnavailable`。`OwnerManaged` 只用于 Core lifecycle 与 version manager 命令，不冒充 engine API evidence。声明通过不代表 product composition 已接入，对应 adapter operation 仍需单独注入，并以 `AdapterMissing` fail closed。
- Mihomo v1.19.18 与 v1.19.32 的 Linux direct smoke 覆盖 CLI `-t` 原生配置检查、`/dns/query`、shell `PUT /configs?force=true` reload/readback、outbound list/select/probe、log-level 写读和 routing intent 写读。Mihomo 官方 API 将 `/configs` 的 `PUT` 定义为带 `force=true` 的 reload；活动 Profile transaction 通过该真实 reload 应用候选，在 reload/readiness 失败时精确恢复旧 workspace，并在锁外预绑定 controller endpoint。Profile transaction nextest run IDs：v1.19.32 `626fc06a-4fa4-4af1-837c-9149c2a7d783`；v1.19.18 `937ba089-9de1-4718-af9d-1d61563306e8`。
- Rust real-process adapter smoke 在两个 Mihomo 版本都打开 `/logs` WebSocket 并收到 `Connected`，验证 typed log-level 写入/恢复、outbound list/select/probe 与 routing 写入/读回。`MihomoRuntime::stream_logs_scoped` 在打开前后检查精确 CoreScope；桌面 scope 回归在 Core/host nextest `6e33cf86-2b6e-4835-992b-d33157132a43` 中通过。adapter real-process nextest run IDs：v1.19.32 `96f85ae3-6d29-486f-9c53-90916d8df181`；v1.19.18 `c2ed93ff-92ea-4555-abec-4aefc3c18e37`。`logs.stream` 的 Linux amd64 operation evidence 已登记；其它目标仍 fail closed。
- Mihomo v1.19.18 与 v1.19.32 的 real-process smoke 还通过隔离 loopback UDP DNS fixture 验证 `/dns/query` 与 typed `DnsQueryPort`：`core-smoke.test` 的 A 查询返回 `192.0.2.42`。adapter nextest run IDs：v1.19.32 `576168d3-53cd-4e53-a589-01cde7a39ac8`；v1.19.18 `0ad9ef53-3911-45d4-bfd2-bf69afc6bd4c`；focused capability nextest `49583c4c-a33d-4146-af4f-608a861cba95`；non-UI Core unified nextest `3be9dc89-9b76-4aa8-abcd-30504c61f52b`（3209 passed、8 skipped）。`dns.query` evidence 只授权锁定的 Linux amd64、adapter revision 1 和这两个精确版本；其它目标与版本仍 fail closed。
- Mihomo v1.19.18 与 v1.19.32 的 real-process smoke 建立了经 loopback SOCKS 入站和本地 HTTP 出站 fixture 的活动连接；typed `RuntimeGateway` 读取连接快照、按精确 ID 执行 `Connection.Close`，再读回确认该连接消失。Mihomo controller 对 `DELETE /connections/:id` 定义 HTTP 204 成功响应（[官方 API 文档](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md)）。adapter nextest：v1.19.32 `64eddd12-70cd-4f0b-9667-d61c29156035`；v1.19.18 `0ce45576-4e39-454f-b417-e926c26c0d74`；non-UI Core unified nextest `3be9dc89-9b76-4aa8-abcd-30504c61f52b`。`connection.close` evidence 与 DNS 一样只授权锁定的 Linux amd64 / revision 1 / 两个版本。
- `CoreGarbageCollection.Trigger` 已由 v1.19.18 与 v1.19.32 的 SHA-locked real-process smoke 验证；该隔离进程从启动时就使用 `log-level: debug`，因为 Mihomo 仅在启动日志级别为 debug 时挂载 `/debug/gc`（[官方 API 文档](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md#debug)）。运行中再 PATCH 成 debug 不会补挂该路由；若 `/debug/gc` 返回 404，`RuntimeGateway` 将它报告为 typed `Unsupported`，不会伪报 GC 失败或成功。此证据不读取 GC 后内存效果。adapter nextest：v1.19.32 `3b26f83a-1720-4c0c-add9-05de91c9dd7b`、v1.19.18 `f8e04d65-fb62-4f79-b02c-0eb0eaed1e93`；profile transaction nextest：v1.19.32 `73a4df68-d0dc-436e-924f-87e2e1aefa09`、v1.19.18 `9bae0a7f-5824-46f5-9ac8-a9e862747db9`；non-UI unified nextest `5613c06a-c03c-4601-9540-044446720046`（3214 passed、8 skipped）。
- `dns.apply_configuration` 与 `rules.apply` 现有双版本 Linux amd64 / adapter revision 1 真实进程证据。Profile smoke 通过 Mihomo codec 与活动配置事务应用 typed `DnsSettingsPatch` 和 `RuleEntry`：DNS 上游切到第二个本地 fixture 后，唯一 DNS 查询返回 `192.0.2.53`；事务恢复原 workspace 后另一唯一查询返回 `192.0.2.42`，且原始 workspace 字节精确恢复。Rules.Apply 写入 `DOMAIN,core-smoke-rule-apply.test,REJECT` 后由 live `/rules` 读回，再恢复原始规则文档。生成的两个候选均先由对应锁定 Mihomo 二进制 `-t` 校验。Application command→ManagedRuntime 的 fake 行为由统一 nextest 覆盖；这份 real-process smoke 验收 adapter codec 与活动 Profile transaction，不证明 UI 行为。v1.19.32 Profile smoke `9e3da32d-1cc7-464f-8ad2-19f4ff1ae231`，v1.19.18 `10ac4134-6755-491d-9663-92e652ad582b`。
- 真实 `/rules` 回包包含 `size: -1`；Mihomo wire DTO 的 `Rule.size` 因此使用有符号 `i64`，保留原始 wire 值，不推断该哨兵的业务含义。`PreferReload` 与 restart fallback 都失败时，typed `ApplyError::ReloadAndRestartFailed` 也保留两种失败原因；rollback receipt 保留该诊断。focused rollback nextest `07af92d8-5eb4-4b21-bd56-66239ef2d8d3`；DNS codec focused nextest `932048d4-c833-4f30-8942-1501ea47b497`；non-UI unified nextest `70c5ea2a-7a78-41a3-9c3f-a89a9ca88243`（3218 passed、8 skipped）。
- Logs.Read 没有 production Core command route，声明为 Unsupported；Logs.Clear 已从 CoreOperation catalogue 退役，只清理本地 LogApplication collector。Android owner、sing-box 及 Linux 以外平台不由这些 Mihomo 测试证明。Connection.List 与 proxy-provider operations 仍为 Unsupported，因为当前产品组合未接入这些 Core operations。
