# Mihomo adapter 约束

> 层级：L3

本页只记录 Mihomo 特有规则；crate 职责见 [README.md](../README.md)。

- `mihomo-api` 封装 REST/WebSocket、wire DTO、鉴权与错误映射；这些类型不得进入共享业务或 UI。
- 运行中 Fake-IP 清理通过 scoped `ControllerFakeIpCachePort` 调用 Mihomo controller。两个锁定 Mihomo 版本都接受 `POST /cache/fakeip/flush` 并返回 `204`（[官方 API 文档](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md)）；typed adapter receipt 绑定请求 scope/operation，但 controller 不提供缓存内容读回，因此该证据不声称读回证明缓存为空。adapter nextest：v1.19.32 `b5961bde-fa5a-4a01-8b1f-72cf3dfd0768`；v1.19.18 `ffabc9df-cb80-48d3-92a6-cf928f154c6f`；non-UI Core unified nextest `4c298ab9-2610-45bc-bb52-e9b611477f4c`（3218 passed、11 skipped）。`fake_ip_cache.flush` evidence 只授权 Linux amd64、revision 2 与这两个精确版本。
- v1.19.18 与 v1.19.32 的 real-process smoke 使用本地 HTTP rule-provider fixture 验证 scope/revision-bound `RuleProviderPort` inventory、payload 和 refresh/readback：初始 `ruleCount=1`，刷新被接受后读回 `ruleCount=2`；HTTP provider payload 如未发布则为 `NotPublished`，不伪造内联规则。官方 `PUT /providers/rules/:name` 返回 HTTP 204（[官方 API 文档](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md)）。typed adapter nextest：v1.19.32 `f7ca5d21-ce14-4f04-8cc9-97577835ef8f`；v1.19.18 `fc28b4f6-6d91-440c-9718-dfaf773c8216`；Core-only unified nextest `f2ec4c8e-1cdf-4396-9623-214740be4974`（2,886 passed、13 skipped）。规则 provider 操作只授权锁定 Linux amd64、revision 2 与这两个精确版本；sing-box 与 proxy-provider 操作均保持 typed `Unsupported`。旧 `RuntimeGateway` provider/payload facade 和旧 runtime provider DTO 路径已退役。
- `mihomo-config` 负责 Mihomo YAML 的解析、校验和持久化；校验失败不得发布配置。
- Mihomo 进程归 `mihomo-process`，版本安装归 `mihomo-version`，共享 OS/host 能力归 `infiltrator-platform`；controller 可用不代表代理/VPN 已生效。
- 凭据不进入日志、普通错误或 UI；流式请求须支持取消、断线处理与有界缓存。
- 产品发行资产版本和摘要只以 [`mihomo-assets.json`](../../../packaging/mihomo-assets.json) 为准；逐操作兼容证据另以 [`mihomo-evidence-assets.json`](../../../packaging/mihomo-evidence-assets.json) 锁定，不能改变发行版本。
- capability provider 启动时校验 [`adapter-operation-declarations.json`](../adapter-operation-declarations.json) 覆盖完整 operation catalogue，并将 Supported evidence ID 与 target-scoped schema v2 evidence asset 锁对应。证据须匹配精确 Core version、完整 Rust `binary_target` triple 与 `adapter_revision`；这些字段也进入 `CoreCapabilityScope`，使跨构建目标或 revision 的结果不能复用。当前 evidence lock 登记 24 个 operation ID：21 个 Mihomo wire adapter behavior、3 个共享订阅应用工作流；订阅证据来自生产 `HttpSubscriptionSource`、loopback-only fixture、同一 engine-scoped Mihomo `ProfileStore` 和每阶段的原生 `mihomo -t` 校验。锁只覆盖 `x86_64-unknown-linux-gnu`、revision 2；Android/iOS/其他 target triple 和 revision 均 `HostUnavailable`，version-bound operation 的版本或 operation evidence 缺失为 `VersionUnavailable`。`OwnerManaged` 只用于 Core lifecycle 与 version manager 命令，不冒充 engine API evidence。声明通过不代表 product composition 已接入，对应 adapter operation 仍需单独注入，并以 `AdapterMissing` fail closed。
- subscription Import/UpdateProfile/UpdateAllSubscriptions 的双版本 nextest 真实进程证据：v1.19.32 `ed80c380-90b8-4491-a4ab-6426c484d44c`，v1.19.18 `6581de2d-2fcc-4046-8997-8bff8072993b`。这验证 loopback 订阅下载、typed report、ETag 条件更新、engine-scoped workspace 持久化与 SHA 锁定 binary 的配置接受；不覆盖公网订阅可达性或 Android 设备运行。
- `geo.update_databases` 双版本真实进程证据：v1.19.32 `6db834c2-3faa-473a-9fcf-d3e1968795ff`，v1.19.18 `fed020e5-c789-4dd7-8f08-44fce6991960`；Core-only unified nextest `f2ec4c8e-1cdf-4396-9623-214740be4974`（2,886 passed、13 skipped）。scope-bound `GeoDatabasePort` 触发请求均被接受，运行配置中的四个 `geox-url` 全部指向 loopback。回执仅表示异步触发已接受；Mihomo 下载及数据库安装不在该证据范围内。sing-box 对应操作保持 typed `Unsupported`。
- Mihomo v1.19.18 与 v1.19.32 的 Linux direct smoke 覆盖 CLI `-t` 原生配置检查、`/dns/query`、shell `PUT /configs?force=true` reload/readback、outbound list/select/probe、log-level 写读和 routing intent 写读。Mihomo 官方 API 将 `/configs` 的 `PUT` 定义为带 `force=true` 的 reload；活动 Profile transaction 通过该真实 reload 应用候选，在 reload/readiness 失败时精确恢复旧 workspace，并在锁外预绑定 controller endpoint。Profile transaction nextest run IDs：v1.19.32 `8a359cd5-8c52-40d4-b159-9f3335f777cd`；v1.19.18 `7fa8109d-a73c-4454-afb0-e483ecdd04a7`。
- Rust real-process adapter smoke 在两个 Mihomo 版本都经 `RuntimeStreamPort::logs` 打开 `/logs` WebSocket 并收到带请求 `CoreScope` 的 `Connected`；`MihomoRuntimeStreamPort` 在打开前后及每个事件上核对 owner scope，application boundary 再拒绝 foreign/late event。真实 adapter nextest：v1.19.32 `9f71d230-601a-400c-b018-2ff3bbb3e13a`；v1.19.18 `59c43f40-dce5-4ebd-8d2c-8e54b45fdbe0`。Core non-UI nextest `6166ec76-4637-4491-81e9-6abbd59ce36a` 为 2893 passed、13 skipped。`logs.stream` 的 Linux amd64 operation evidence 已登记；其它目标仍 fail closed。
- Mihomo v1.19.18 与 v1.19.32 的 real-process smoke 还通过隔离 loopback UDP DNS fixture 验证 `/dns/query` 与 typed `DnsQueryPort`：`core-smoke.test` 的 A 查询返回 `192.0.2.42`。adapter nextest run IDs：v1.19.32 `b5961bde-fa5a-4a01-8b1f-72cf3dfd0768`；v1.19.18 `ffabc9df-cb80-48d3-92a6-cf928f154c6f`；focused capability nextest `4c298ab9-2610-45bc-bb52-e9b611477f4c`；non-UI Core unified nextest `4c298ab9-2610-45bc-bb52-e9b611477f4c`（3218 passed、11 skipped）。`dns.query` evidence 只授权锁定的 Linux amd64、adapter revision 2 和这两个精确版本；其它目标与版本仍 fail closed。
- Mihomo v1.19.18 与 v1.19.32 的 SHA-locked real-process smoke 均通过共享 `ConnectionPort::observe`/`close`：建立 loopback SOCKS→Mihomo→HTTP 活动连接，以 engine-scoped ID 和 observation revision 发出关闭，再读回确认连接消失。Mihomo controller 对 `DELETE /connections/:id` 定义 HTTP 204 成功响应（[官方 API 文档](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md)）。typed adapter nextest：v1.19.32 `476fe72f-e109-4534-9b2b-9ac6a40fa17a`；v1.19.18 `6f034e1d-2b4b-4c7d-b716-bbda198f5185`；Core unified nextest `2f61e785-3236-4c36-915d-bac32ec15fc0`（2396 passed、4 skipped）。`connection.close` evidence 仅授权锁定的 Linux amd64 / adapter revision 2 / 两个精确版本；Connection.List 仍 Unsupported，Android 与 sing-box 行为不由本证据覆盖。
- Mihomo resource observations use `CoreResourcePort` and carry the requested `CoreScope`. The [`/memory` endpoint](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md#memory) is a continuous stream; the client parses the first complete nonzero sample and drops the response, avoiding a wait for stream termination. Scoped GC returns `Collected` only with same-scope post-GC memory readback; a missing `/debug/gc` endpoint is `Unsupported` because Mihomo mounts it only when startup log level is debug ([official API](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/api/index.md#debug)). Real-process smoke passed v1.19.32 `a7d7af69-a7e0-4848-9a89-5618b44373c2` and v1.19.18 `4755baf3-e7fc-4a55-94e8-9d77e05f7acb`; Core nextest `02381073-77eb-4598-a370-1be254e10bcf` (2967 passed, 13 skipped). This validates Linux amd64 Mihomo; it does not validate Android or sing-box resource support.
- `dns.apply_configuration` 与 `rules.apply` 现有双版本 Linux amd64 / adapter revision 2 真实进程证据。Profile smoke 通过 Mihomo codec 与活动配置事务应用 typed `DnsSettingsPatch` 和 `RuleEntry`：DNS 上游切到第二个本地 fixture 后，唯一 DNS 查询返回 `192.0.2.53`；事务恢复原 workspace 后另一唯一查询返回 `192.0.2.42`，且原始 workspace 字节精确恢复。Rules.Apply 写入 `DOMAIN,core-smoke-rule-apply.test,REJECT` 后由 live `/rules` 读回，再恢复原始规则文档。生成的两个候选均先由对应锁定 Mihomo 二进制 `-t` 校验。Application command→active-profile applier 的 fake 行为由统一 nextest 覆盖；这份 real-process smoke 验收 adapter codec 与活动 Profile transaction，不证明 UI 行为。v1.19.32 Profile smoke `8a359cd5-8c52-40d4-b159-9f3335f777cd`，v1.19.18 `7fa8109d-a73c-4454-afb0-e483ecdd04a7`。
- 真实 `/rules` 回包包含 `size: -1`；Mihomo wire DTO 的 `Rule.size` 因此使用有符号 `i64`，保留原始 wire 值，不推断该哨兵的业务含义。`PreferReload` 与 restart fallback 都失败时，typed `ApplyError::ReloadAndRestartFailed` 也保留两种失败原因；rollback receipt 保留该诊断。focused rollback nextest `07af92d8-5eb4-4b21-bd56-66239ef2d8d3`；DNS codec focused nextest `932048d4-c833-4f30-8942-1501ea47b497`；non-UI unified nextest `4c298ab9-2610-45bc-bb52-e9b611477f4c`（3218 passed、11 skipped）。
- `tun.configure` 现有双版本 Linux amd64 / adapter revision 2 真实进程证据。Smoke 通过 `RuntimeConfigurationApplication` 写入 `system → mixed → system` 并逐次核对 scope、revision 与 controller readback；全过程 `tun.enable=false`，不创建宿主 TUN。v1.19.32 nextest `266b6d65-fb2c-4b73-bd91-f119b7423028`，v1.19.18 `c9a16fec-b62e-4c66-9673-c46ed9896922`；application/adapter fake 回归 `ccc890e3-18a1-435c-9862-32bcbdbb72b4` 为 9/9。
- `profile.apply_feature` 现有双版本 Linux amd64 / adapter revision 2 真实进程证据。`RuntimeConfigurationApplication::set_ipv6_routing` 从 live readback 的 `false` 应用为 `true`，再恢复 `false`；每次由 application 与 Mihomo adapter 比较 scope/revision/value 并复读确认，`tun.enable` 始终为 `false`。v1.19.32 nextest `5ae2637c-f3b0-4d5e-8025-5346b720b43d`，v1.19.18 `9fea92e1-629e-4fd0-a571-be0cef4a7ee9`。这证明隔离 Core 配置操作，不证明系统 VPN 或宿主网络变化。
- `rules.trace` 现有双版本 Linux amd64 / adapter revision 2 真实进程证据。Smoke 从与运行中 Mihomo 相同的 profile 文件经生产 `ProfileApplication`/YAML codec 读取规则，并从 live controller 获取 scoped typed outbound observation；共享 `RuleTracerApplication` 以真实 owner/workspace identity 完成 Live trace，命中 `DOMAIN,core-smoke-active.test,CORE-SMOKE-HTTP`，并按 typed outbound ID 解析 `CORE-SMOKE-HTTP`。只读 `RuleOverridePort` 由测试组合注入；该证据不覆盖反向应用规则或 UI command ingress。v1.19.32 nextest `f2f24a6d-d409-42a4-a23c-c7bfa68ae6a2`，v1.19.18 `2d637629-c8b2-43f9-8984-96787c869604`；统一非 UI nextest `4c298ab9-2610-45bc-bb52-e9b611477f4c` 为 3218 passed、11 skipped，含 exact-scope capability/declaration 回归。
- Logs.Read 没有 production Core command route，声明为 Unsupported；Logs.Clear 已从 CoreOperation catalogue 退役，只清理本地 LogApplication collector。Android owner、sing-box 及 Linux 以外平台不由这些 Mihomo 测试证明。Connection.List 与 proxy-provider operations 仍为 Unsupported，因为当前产品组合未接入这些 Core operations。
