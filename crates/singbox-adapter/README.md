# singbox-adapter

> 层级：L3

This crate owns the sing-box process, loopback readiness, native JSON boundary, and the sing-box-specific Clash API adapter. Clash API requests require an owner-supplied `CoreScope` with engine `sing-box`, the provider's exact `CoreInstanceId`, a live API version match, and a matching `OutboundScopeSource` observation. A source that switches to another instance fails closed before controller dispatch.

The live version provider reads `/version`, requires the `sing-box ` identity prefix, and returns a canonical `v<version>` value. `/proxies` maps named entries into the engine-neutral inventory, excludes sing-box's synthetic `GLOBAL` compatibility entry, marks only `Selector` as manually selectable and `URLTest` as automatic, and keeps unknown group types non-writable. A selector write sends `PUT /proxies/{tag}` with `{"name":"<member>"}` only after a fresh inventory/revision check, then requires `/proxies` readback to confirm the selected member. The adapter serializes its own operations; sing-box does not expose controller-side CAS, so direct writers outside this adapter are not covered by that revision fence.

`SingBoxProfileConfigurationTransactionAdapter` binds the native validator and config-file owner to a sing-box-namespaced `ProfileStore` CAS and the same Core engine instance as the provider process. While Stopped or Failed it validates the candidate with the official binary, CAS-publishes the document/sidecar, installs the exact native JSON bytes, verifies both readbacks, and restores both previous values after a failed publication. It rejects Ready/Running as typed `Unsupported` before native dispatch or persistence because live apply/restart behavior is not verified. A shared operation gate serializes this transaction against process start/stop; each config path still requires exactly one adapter owner.

The current Clash mode is exposed only as `EngineDefined(sing-box, mode.<lowercase-mode>)` after `/configs.mode` is present in `/configs.mode-list`. All routing-intent writes remain typed `Unsupported`: sing-box documents `default_mode` as a selector for `clash_mode` rule branches, not as a direct traffic-routing policy. Outbound protocol details and delay probes also remain `Unsupported`; `/proxies` does not provide neutral protocol/cipher configuration facts, and `/proxies/{tag}/delay` has URL and URLTest-group side effects that have not been proven safe for this contract. These boundaries follow the official [Clash API documentation](https://sing-box.sagernet.org/configuration/experimental/clash-api/), [Selector documentation](https://sing-box.sagernet.org/configuration/outbound/selector/), and the immutable [v1.14.3 `clashapi` source](https://github.com/SagerNet/sing-box/tree/v1.14.3/experimental/clashapi).

The locked release and platform archive digests are recorded in [`sing-box-evidence-assets.json`](../../packaging/sing-box-evidence-assets.json), using target-scoped schema v2 with an explicit binary target and adapter revision per asset. These asset digests do not establish per-operation behavior. The official v1.14.3 binary has been manually exercised for `/version`, selector `/proxies` shape, selector PUT, and `/configs` mode-list. `SingBoxEngineBackendProvider` builds the production process/readiness/codec/transaction bundle and typed Clash outbound/routing ports. Production-provider conformance passed in the focused fake suite (`91abed5f-ac17-4006-844e-f09a590e037e`, 2/2) and the SHA-locked real-process suite (`a7e148c8-4bd5-48b5-9560-271d01ec88e4`, 2/2); the real suite binds provider process identity to its typed transaction owner and exercises profile validation/readback plus fail-closed no-change behavior. No desktop or Android product root selects sing-box yet, so unselected product capabilities remain fail-closed. The suite does not establish support for operations that remain typed `Unsupported`, and asset hashes alone do not make product operations available.

The SingBoxEngineVersionBackendFactory implements the shared VersionPort and CoreBinarySelectionPort without mihomo-version::VersionManager. It resolves the current Cargo target against the embedded immutable asset lock, stores binaries and selection state under home/engines/sing-box/targets/<binary-target>/, verifies the archive digest and extracted binary-reported version before atomic publication, and rechecks the receipt, binary digest, target, and adapter revision before activation or selection. Only ManagedOnly selection is supported; bundled fallback policies return typed Unsupported.
