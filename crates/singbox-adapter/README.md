# singbox-adapter

> 层级：L3

This crate owns the sing-box process, loopback readiness, native JSON boundary, and the sing-box-specific Clash API adapter. Clash API requests require an owner-supplied `CoreScope` with engine `sing-box`, a live API version match, and a matching `OutboundScopeSource` observation.

The live version provider reads `/version`, requires the `sing-box ` identity prefix, and returns a canonical `v<version>` value. `/proxies` maps named entries into the engine-neutral inventory, excludes sing-box's synthetic `GLOBAL` compatibility entry, marks only `Selector` as manually selectable and `URLTest` as automatic, and keeps unknown group types non-writable. A selector write sends `PUT /proxies/{tag}` with `{"name":"<member>"}` only after a fresh inventory/revision check, then requires `/proxies` readback to confirm the selected member. The adapter serializes its own operations; sing-box does not expose controller-side CAS, so direct writers outside this adapter are not covered by that revision fence.

The standalone `SingBoxProfileConfigurationAdapter` serializes native config apply transactions from validation through readback/rollback within one adapter instance. Each config path must have exactly one adapter owner; different instances or processes sharing the path are outside this lock and are unsupported. The shared backend conformance suite currently reaches this helper through a test-only `NativeProfileFixturePort`; that is not the production typed transaction port required by CORE-013.4, so configuration transaction conformance remains open.

The current Clash mode is exposed only as `EngineDefined(sing-box, mode.<lowercase-mode>)` after `/configs.mode` is present in `/configs.mode-list`. All routing-intent writes remain typed `Unsupported`: sing-box documents `default_mode` as a selector for `clash_mode` rule branches, not as a direct traffic-routing policy. Outbound protocol details and delay probes also remain `Unsupported`; `/proxies` does not provide neutral protocol/cipher configuration facts, and `/proxies/{tag}/delay` has URL and URLTest-group side effects that have not been proven safe for this contract. These boundaries follow the official [Clash API documentation](https://sing-box.sagernet.org/configuration/experimental/clash-api/), [Selector documentation](https://sing-box.sagernet.org/configuration/outbound/selector/), and the immutable [v1.14.3 `clashapi` source](https://github.com/SagerNet/sing-box/tree/v1.14.3/experimental/clashapi).

The locked release and platform archive digests are recorded in [`sing-box-evidence-assets.json`](../../packaging/sing-box-evidence-assets.json), using target-scoped schema v2 with an explicit binary target and adapter revision per asset. These asset digests do not establish per-operation behavior. The official v1.14.3 binary has been manually exercised by the root task for `/version`, selector `/proxies` shape, selector PUT, and `/configs` mode-list. The production engine factory currently registers Mihomo only, so sing-box's standalone profile validation/apply, outbound list/select, and routing-read adapters remain declared `Unsupported` until their owner composition is registered. The shared fake behavior test and both ignored real-process conformance tests have not been run. The real test's config fixture is not a production configuration port and cannot close CORE-013.4; the unified real-process result and operation evidence remain open. Neither test fixtures nor asset hashes alone make operations available, and no mock or source inspection is registered as real operation evidence.
