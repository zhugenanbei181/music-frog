# Bevy UI 前端章程

本文是 Bevy UI 前端工具链与实现方式的权威说明。Bevy UI 与 Iced 是同权的独立发行产品，遵循 [UI_PARITY_AUDIT.md](UI_PARITY_AUDIT.md)；不存在维护端与战略端的业务地位差别。Bevy 保留 ECS、`bsn!` 场景树、Observer 与图形渲染优势；平台覆盖与交互缺口分别记录，不能因控件生态差异缩减业务操作深度。
参考实现：taskmanager 的 `taskmanager-bevy-ui`（同为 bevy 0.20 产品级 UI，bsn! 场景法
+ 观察者绑定 + 纯核/场景适配器二分 + 中立主题 token）。本章程的多条铁律直接来自该
项目的成文法律与踩坑记录。

## 1. 基座铁律

- **bevy 锁定 `=0.20.0-rc.2`**：精确到 patch，与 taskmanager 同锁。升级属于架构与发布
  评审事项（bevy 0.20 已把 UI 布局与渲染拆开，`bevy_ui` 单独只排版不上屏，必须闭合
  `bevy_ui_render`）。
- **依赖边界**：`infiltrator-bevy-widgets` 使用 Bevy、Unicode 文本处理与 `infiltrator-shared` 的中性本地化资源；禁止持有第二套产品文案表或引入 application/宿主/内核依赖。`infiltrator-bevy-ui` 依赖
  bevy + widgets + `infiltrator-contract` + `infiltrator-application`、前端中性的只读 `SurfaceReader` 端口与组合根，但不依赖
  `infiltrator-core`、`mihomo-api`、Reqwest 或 Tokio。具体 Mihomo adapter 由
  `infiltrator-composition` seam 提供，不能进入页面与 projection 模块。
- **feature 闭包两段式声明**：`[dependencies]` 空特征基座声明 + per-target 表持有
  真实闭包（bevy derive 宏按 `::bevy::…` 路径扫描普通依赖表，只写 target 表会
  unresolved）。`default-features` 全关（无音频/gilrs/3D/动态链接）；`multi_threaded`
  关闭以保证无头测试可在 app 线程内观察渲染路径；当前 Linux Bevy 闭包仅启用 Wayland，
  X11 支持缺口单独记入平台矩阵，两端的独立发行与同权产品地位不变。
- **100% `bsn!` 场景法**：生产 UI 树（页面、行/单元格、控件、覆盖层）全部由 `bsn!`
  场景组合并经 `spawn_scene` 挂载；禁止命令式 `Node{}`/`Children`/`with_children`
  另起 UI 树。ECS 系统只更新场景实体的 typed 组件、接线事件/焦点，或以新场景替换
  有界子树。机械红线由 `scripts/quality/bevy_bsn_guard.py` 强制（001–004 与
  taskmanager 对齐，005/006 为本项目加严）：
  - **结构/状态划线**：结构原语（`Node`/`Children`/`Text`）只能在场景内声明，
    运行时只许原地改字段（`node.width = …`）；状态组件（`ImageNode`、颜色、标记位）
    允许观察者盖章——红线封的是结构旁路，不是 ECS。
  - **BEVY-BSN-005 临时值即旁路**：结构原语的 `::default()`/`::EMPTY`/`::new`/
    `::from_*` 构造出现在场景外即违规——"先落占位值、再命令式补写"与字面量旁路
    同罪；`accesskit::Node::new`（无障碍树）是唯一机械豁免。
  - **BEVY-BSN-006 挂载缝唯一**：`insert(ChildOf(…))` 只能是
    `spawn_scene(…).insert(ChildOf(…))` 同一语句链的尾环；独立 reparent 禁止，
    改挂载 = 替换有界子树。
  - **BEVY-BSN-002/003 层级 API 全封**：`insert_children`/`replace_children`/
    `add_related`/`insert_related`（含 turbofish）、`spawn_empty(_at)`、
    `ChildSpawner(Commands)`/`RelatedSpawner(Commands)` 类型声明均违规；
    `despawn_children`/`remove_child(ren)`（拆除路线）允许。
- **状态更新与结构生命周期分开**：身份与结构不变的运行时变化由 `On<Insert<…>>`/`On<Activate>` 等观察者原地更新 typed 组件。列表新增、删除、身份重排或链路层级变化由专属列表 owner 比较结构身份，在 `Commands` 延迟提交边界用 `bsn!` 场景替换对应有界子树；不得只更新最初挂载的固定行数，也不得每帧重建页面。资源或语言变化不重建业务实体，原生文本通过共享本地化回放。结构提交后再按当前查询恢复可见性与顺序，不接收整个 `World`。
- **搜索文字回放**：匹配、原始文字片段和结果数由共享 application owner 产生。控件层只回放中性 `SearchTextRun`，保留字形簇、大小写与元数据来源；不在 ECS 或 TEA 渲染内另建匹配算法。原生文字与查询实体在查询、语言、主题变化时保留身份，内部 TextSpan 只在内容结构变化时替换。不可用读数与成功空结果必须分开，不能将缺失观测渲染成搜索无匹配。
- **聚合列表完整性**：原生聚合操作面必须回放共享 application owner 的完整分组行、成员数和流量。搜索先参与共享折叠，维度切换、连接刷新及返回平铺均保留当前查询；不能用前几组摘要替代完整分组列表。排序控件对应的字段必须来自真实共享事实，缺失时间戳不能假装支持最新优先。
- **实时日志事实 owner**：日志流、容量、稳定行身份、会话隔离与级别解析归共享 application；原生页面只读不可变日志快照。不能以固定演示行数替代真实流，也不能为未知级别补 INFO。正则编译、匹配、字形簇片段和错误状态由共享 `LogSearchState` 一次折叠，原生 `TextRuns` 回放并保留级别色阶；语言与路由变化保留查询。失效与成功空缓冲分别展示；清空和级别筛选提交到该快照的同一 owner，不在页面 observer 中维护第二份事实缓冲。连接打开、重连等待和空闲读取都必须能取消，退出产品释放驱动及接收者。
- **日志滚动与接收分离**：锁定只固定原生视口，不能停止共享日志接收。自动跟随、手动查看历史、锁定与恢复由共享滚动策略决定；原生层在实际布局完成后回放位置，日志增长或实体重新挂载不能覆盖锁定位置。验收必须检查真实 SDK 滚动位置及继续接收的记录，不能只断言按钮文案或布尔状态。
- **ECS 访问边界**：业务、页面、控件交互和场景激活系统禁止接收 `World`、`&World`、`&mut World` 或通过闭包、包装器、泛型透传整个 World。只声明所需的 `Query`、`Res`、`ResMut`、`Commands`、`On`；相关参数可以组成职责明确的 `SystemParam`，不得聚合为全局服务定位器。截图激活器同样遵守，不得以测试模式调用业务状态旁路。
  `BEVY-ECS-007` 在既有 Bevy 结构守卫中阻断生产代码的 `World`、`DeferredWorld`、`EntityWorldMut`、`UnsafeWorldCell` 与 `SystemState` 类型入口，不增设业务白名单；该检查只证明访问边界，真实交互与像素仍分别验收。
- **装配与生命周期边界**：页面插件在 `Plugin::build` 中一次注册资源和业务观察者，页面根组件只标记实体身份；禁止用页面 `on_insert` hook 懒注册业务系统、访问全局资源或重置草稿。组件插入初始化使用 `On<Insert<T>>` 与对应 `Query`、资源、`Commands`，不接收 `DeferredWorld`；运行态同步不能使用独占系统获取整个 World。
  业务函数也不得改收 `App` 再调用 `world()` / `world_mut()` 取得整个 World。装配只能安装插件、资源、场景和系统；进入运行态后通过已注册系统的受限参数完成交互，截图激活不构成例外。
  `BEVY-ECS-008` 禁止生产代码调用 `world()` / `world_mut()`，包括 `Plugin::build`；框架注册使用 `App` 的注册 API，字体与图标初始化使用受限资源系统，在 `PreStartup` 完成并先于场景激活。截图 `install` 只注册隔离资源与系统，不直接修改业务快照。插件装配不构成业务访问或字体/图标访问的豁免。
- **请求与事实边界**：一次用户操作所需的查询与沙盒参数必须进入同一个 typed 意图，不能拆成两个可交错的命令。运行态 reader 只回放共享 owner 的结果，不触发模拟或累计统计；终态按请求身份接收，读取失败保留上次报告。模拟输入、运行时观测与未观测值明确区分，不从端口号推断已发生 TLS 嗅探，不补造来源地址、协议或策略组调度结果。
- **控制观测独立性**：偏好页成功、内核运行与控制器配置成功分别表示不同事实。模式、脚本能力和 TUN 使用共享可选观测，不把缺失值补成 Rule、可用或关闭。读取失败保留同一代次的旧值并禁用写入，新代次清理旧值；原生模式标签回放共享“未观测／切换中／已失效”状态。命令成功回执不能提前替代实际配置读回，状态灯回放实际生命周期。
- **遥测观测与曲线来源**：速率文案、峰值和状态回放共享读数 owner，不能用默认数值或私有传输连接状态补造观测。首次采样尚未形成速率时显示未观测，实际零速率保留为零，读取失败保留同一会话的失效值与原因；新代次或新 token 退役旧值与曲线。实时曲线始终读取共享 waveform，空曲线和单个真实样本不得回退到旧 UI 历史或演示波形。语言与主题刷新原位更新文本，不重建业务实体。
- **写入请求与读回隔离**：模式动作由共享 `proxy_mode_actions` 状态机维护请求身份、代次和类型化终态，禁止另设成功布尔值或在 UI 重复折叠事实。开始与结束写入均退役此前配置读取，写入期间的读取不能覆盖已验证回执；新鲜读回仍可报告外部修改。失败保持实际生命周期与最后观测，原生操作面明确提供适用的重试和关闭，健康轮询不自动吞掉写入失败，认证失败不得伪装成可重试网络错误。
- **多入口同一状态机**：侧栏、概览分段器、命令面板和截图激活不能各自建立控制写入路径；通过同一 typed 请求进入共享动作 owner，统一等待、禁用、实际回执和失败恢复。认证/权限失败保留原因与事实，提供原生设置引导，不静默重复执行原写入。
- **设置观测与输入门控**：设置渲染读取共享 owner 的完整运行观测，偏好页失败不能抹掉已观测的控制器事实。缺失子字段明确为未知，不能作为关闭状态执行切换；控件 SDK 和提交 Observer 同时按实际观测与读取状态门控。禁用同步在页面退役后的 `PostUpdate` 运行并先于 SDK 同步提交，不以整个 World 修改控件或缓存。
- **配置与观测分离**：启用 WebDAV 不证明已连接；同步状态使用共享类型化状态。快照历史缺服务、读取失败和实际空集合分别呈现；缺少大小不能显示为零。冲突字段只能来自实际观测，不能显示固定规则数、节点差异或假选择。无数据时禁用 SDK 输入与可见样式；条件卡片隐藏完整容器，后续真实状态必须可见。
- **配额与更新计划**：可缺失流量字段从端口到契约保持 `Option`，缺字段不能补零，零总额不能标成无限制；累加溢出不能伪装成精确统计。百分比和计划文案只消费共享折叠，周期缺失不默认 Cron，暂停计划保留已存配置。语言回放只改展示，不触碰真实输入、选择或未提交草稿。
- **偏好控件真实值**：托盘与通知等偏好从共享设置观测读取 `Option`，未知值不能默认开启。原生开关、状态文案、无障碍值与提交 Observer 使用同一观测；命令携带明确目标值，不发送后端无法解析的 `toggle` 字符串。入队不能更改已观测事实；失效、缺少服务和未知值同时阻断 SDK 与直接激活事件。
- **测速事实完整性**：带宽、丢包、抖动和稳定性各有独立观测前提。仅带宽或出口测量不能证明丢包评级与星级；真实零值保留，未测量显示未知；抖动需要至少两个成功 RTT 样本，全部超时或仅一个成功样本不能显示成零抖动，但实际丢包率仍保留。摘要、历史与详情统一消费共享投影；语言回放更新文案和输入提示，保留测量结果、模态、草稿、选择与焦点，不提交命令。
- **确认与源身份**：规则反向应用等配置写入先展示原规则、目标和源配置的确认面板，取消不提交命令。确认请求绑定源配置身份、内容哈希与原始规则；宿主在事务中校验并固定写入路径，源变化直接拒绝。失败保留面板与目标供重试，不通过手改 UI 列表发布持久化成功。
- **多入口表单与类型化结果**：同一业务在工作台、文档 Tab 或模态出现时复用共享纯状态机，原生层只维护焦点、IME、实体身份和请求接线，不另设草稿、成功通知或键盘处理副本。过滤表单绑定首次观测的配置与选项字节来源，保存不得改用当前选中的配置；只修改表单拥有的字段；未携带高级策略的旧调用保留已存值，显式高级映射在共享层校验，空映射才清除。工作台与文档入口提供同等原生高级策略输入，字段语义与失败原因由共享 owner 回放。提交通过宿主注入的中性命令边界，终态须携带实际提交来源与详细报告；接受入队、无结果的成功和错误结果类型都不能完成表单。平台不支持保留类型化原因，缺少服务不触发 UI 私自构造宿主 adapter。
- **调度与延迟提交**：依赖实体生命周期的系统必须声明顺序和 `ApplyDeferred` 边界。页面投影、行退役在 `Update` 完成，控件 SDK 禁用状态通过受限查询在 `PostUpdate` 读取存活实体并在 UI Prepare 前提交。禁止靠独占 World、消音命令错误或忽略实体代次来掩盖调度缺陷。同帧退役、按压取消与恢复必须有真实回归证据。
- **错误可读性**：错误操作面以可读正文承载原因，以共享错误色边框或图标标记语义；不能仅把正文染成低对比度的强调色。实际像素测量与目视核验同时覆盖，结构和非空截图不证明可读。
- **原生输入闭环**：控件必须接通实际指针、键盘和 IME 事件；显示文本状态或在测试里直接改组件不能证明可编辑。普通受控输入须显式采用控件层的 `NativeTextField` 接线；仅挂载 `TextField` 或静态字段标记不能证明支持原生编辑，专用编辑器保留唯一键盘 owner，禁止重复消费同一按键。禁用、组合输入、焦点保留与路由取消均需行为证据。IME 窗口在输入框切换期间可保持启用，新字段的 Preedit 必须开始自己的事务，不得依赖重复收到 Enabled。共享字段枚举的每个原始文本字段均须在原生场景中可编辑，禁止用手写子集排除遗漏字段。
- **原生文档编辑**：多行脚本、YAML 等文档输入优先使用锁定 SDK 的 `EditableText` / `TextInputPlugin`，保留选区、粘贴、换行和原生 IME 的单一事件 owner。SDK 输入可通过真实键盘、指针和 IME 消息无头驱动（消息通道、逻辑按键状态、指针状态须显式装配），不得以“不可测试”为由退化成只读文本或自行重复接管同一按键。共享草稿拥有业务字节；控件缓冲仅承载编辑展示。SDK 文本插件自动提供的剪贴板资源不能证明产品宿主已装配复制能力；业务复制须显式装配宿主入口，并按实际系统结果确认，缺入口返回可见不支持。运行和确认绑定冻结的完整输入，取消不写文件；原生终态须按请求身份接收。SDK 编辑提交位于布局后、`PostLayout` 前，依赖其结果的工作台不得反向排序到 `Prepare` 前；同帧业务禁用与临时屏蔽须通过受限查询提交，再完成 SDK 状态和无障碍同步。
- **输入与覆盖层隔离**：IME 组合期间禁用提交控件，保持输入框可编辑。模态打开后，背景输入、预设和提交控件均不可操作；取消按钮与 scrim 取消调用同一状态机，待提交事务不可被关闭动作伪装为已取消。隐藏 Tab 和路由退出必须释放输入焦点，切换语言不得重挂载正在编辑的输入实体。
- **临时交互屏蔽不改业务事实**：模态隔离使用独立的 typed 屏蔽组件，不能覆盖领域禁用标志。SDK 交互、无障碍和可见色阶读取同一有效禁用状态，屏蔽时清理按压与输入焦点，关闭后按存活实体恢复；清空统计等命令必须关联请求、完整来源与递增回执版本，并等待真实读回，不能把 `Unit` 或旧快照当作成功。
- **草稿生命周期**：页面实体可随路由退役，未提交查询、沙盒元数据与出口草稿由对应的持久 UI 状态保存。新实体只进行一次受限参数初始化，不能用上次报告输入覆盖草稿；reader 刷新不得清除输入或重新执行用例。预设来自共享清单，在小视口换行，不能裁掉按钮或猜测用户配置的出口。
- **规则行统计来源**：行命中数与遮蔽状态只回放共享规则行投影。未提交草稿通过共享折叠映射原行事实，禁止从连接缓存另算命中或用累计数量猜测最近命中。当前计数是本地规则追踪产生的模拟统计，计数和耗时绑定完整配置来源，读取仅回放不可变结果，不增加统计。历史追踪报告与当前规则统计分开发布，双端须明确标注“本地追踪命中”；缺少观测与真实零值分别显示；未发布行以及来源不符的草稿不得借用其他文档的计数，源身份同时核对配置名和内容哈希；清空请求携带该身份，用例与模拟共用准入边界，加载并验证实际源后才清空相同 scope。旧按钮请求不能清空新配置的统计。语言切换原位更新统计文本，不重挂载规则行。
- **列表身份**：显示索引只负责布局与分页，不作为编辑命令身份。行控件携带共享草稿 owner 的稳定行 ID；同帧重排或插入后仍操作原行，删除、取消与源切换后拒绝旧 ID。实体代次和业务行身份分别校验，不能只依靠下一帧重建列表挡住排队点击。
- **未提交表单来源**：构建器开始编辑时绑定实际配置身份与内容哈希。reader 采用新文档不能悄悄迁移旧表单；保留输入，显示旧来源，禁用不再有效的添加与预设动作，并提供独立丢弃表单入口。只有显式丢弃才清空输入并绑定当前文档，取消不写入。
- **外部语义实证**：涉及 mihomo 配置或规则时，以锁定版本的解析与实际行为为准。缺少元数据、外部规则集或子规则表时返回类型化未确定结果，禁止当作不匹配继续落到 `MATCH`。逻辑条件必须保留树形证据；命中的 `SUB-RULE` 名称是子规则表引用，不能显示成已选择的出口。构建器输出须经真实内核解析验证，不能用本地解析器自证兼容。
- **纯核 + 场景适配器二分**：控件 = 零 bevy 依赖的纯函数核（状态机/投影/窗口数学，
  无头可测）+ 消费纯核输出的 `*_scene` 适配器（返回 `impl Scene`）。
- **主题 token 的权威与适配**：双端共同消费的颜色、间距与圆角由 `infiltrator-contract/src/design_tokens.rs` 定义。业务无关的控件 crate 在 `theme.rs` 保留受行为测试约束的镜像，`palette.rs` 负责转为 Bevy 值；改动共享令牌必须同时更新镜像并通过双端令牌一致性测试。调用点禁止裸颜色字面量。不采用 Bevy 官方 Feathers 皮肤。
- **图标走位图，不走字形码位**：嵌入字体不保证装饰性 Unicode 字形，字形 tofu 是
  已知坑（taskmanager 成文教训）。图标 = SVG 派生 RGBA 位图 → tinted `ImageNode`。

## 1.1 新增与重构的实施顺序

1. 先确定共享意图、投影和 application owner。UI 的事件回调只提交 typed 意图，读取完成事件或不可变投影；不在系统中重做领域判断，不持有宿主控制器。
2. 用 `bsn!` 场景声明可视交互面，以 typed 组件标记控件与有限子树。`On<Activate>`、键盘和 IME 系统只声明实际使用的资源与查询；参数较多时按单一职责定义 `SystemParam`，不能把所有页面状态塞入一个参数对象。
   重复或复杂的查询定义职责明确的 `QueryData` / `QueryFilter`，可变查询必须证明互斥。不得以 `allow(clippy::type_complexity)` 或 `allow(clippy::too_many_arguments)` 代替职责拆分，也不得定义纯类型别名隐藏查询。
   `BEVY-ECS-009` 阻断这些 lint 的 `allow` / `expect` / 条件豁免及全局 warnings/clippy 消音；严格 Clippy 检验剩余类型复杂度。结构边界通过仍不代替原生交互回归。
3. 明确状态归属：未提交草稿由对应页面状态持有，命令执行结果由共享 owner 持有，实体只承载渲染与输入状态。销毁实体不销毁需要恢复的草稿；reader 刷新不触发命令。
4. 实体创建、退役和 SDK 状态同步有依赖时，在 schedule 中声明顺序并安排 `ApplyDeferred`。观察者在插件装配时注册；组件初始化由受限生命周期 Observer 完成。异步任务、配置写入、场景激活和业务折叠必须进入普通系统或 application。
5. 重构移除原旁路及其调用者，不同时保留两个运行实现。按实际输入事件验证提交、取消、错误与重试，再以当前源码生成交互截图。结构门禁通过只代表结构符合规范。

原位本地化由控件层 `infiltrator-bevy-widgets::localization` 定义 `UiLocale`、`LocalizedText`、`LocalizedLabel` 与 `LocalizedPlaceholder`；产品插件只读取共享语言偏好。不得在产品层转发这些类型，也不得缓存某种语言的业务状态文案。事实到状态文案的折叠由共享 Application owner 处理，场景仅回放结果。运行态文案和无障碍标签必须随语言更新，原实体、草稿、焦点、选择范围与 IME 预编辑状态保持有效；语言回放不得提交业务命令。

编辑器、Mixin 与 Diff 的目录不得同时保存某端 locale key 和另一端固定语言标签。预设、流水线阶段、列角色使用类型化的中性身份；文案、保护提示、事务结果、诊断位置与行数摘要由共享 application owner 折叠。投影 Observer 负责事实接纳，正常调度的受限系统负责语言回放；语言变化不能重建输入子树或改写缓冲区、光标、焦点、选择、IME 与未提交草稿。光标显示列按 Unicode 字符折叠，不能将 UTF-8 字节偏移直接显示为列数。重型 YAML 预检与合并只在事实变化或新场景挂载时执行，禁止为语言回放在每个空闲帧重复合并。

错误说明和恢复建议也复用同一语言资源与单次插值器；类型化错误只映射键和原始参数，不在 ECS 系统中按语言拼接译文。模板参数一致性门禁与运行态语言回放分别验收，不能相互替代。

产品文案统一复用 `infiltrator-shared`，静态节点在真实控件上声明 `LocalizedText` / `LocalizedLabel`；动态快照文案由 `application::snapshot_presentation` 与恢复投影统一生成。不得把译文写入 contract、按环境变量固定模态标签、用导出键命名恢复操作或从文字反查翻译键。语言切换仅回放文本与无障碍标签，保留行实体、完整历史、选择和真实来源身份；演示身份复用 composition 的中性夹具，真实用户字符串不翻译。

快照恢复入口不得直接提交路径或兼任第二次确认按钮。Diff、历史与同步入口只触发类型化打开事件，由共享恢复工作台提交准备请求；独立审阅层展示完整冻结内容、实际配置身份和哈希，再提供确认、取消、错误与权限重试。终态同时核对请求 ID、操作代次与完整意图；取消和成功后的旧身份不可重放。审阅期间同步屏蔽 SDK 后台控件、编辑器键盘与全局快捷键，关闭后只恢复仍存活的焦点与控件。所有接线和像素激活继续使用受限资源、Query、Commands 与 SystemParam。

枚举选择必须消费共享契约的完整值域。不能以布尔开关折叠多个业务策略，也不能在保存时把未经修改的值换成默认项。未提交选择绑定配置身份与已观测基线；读取重放不覆盖新草稿，来源变化须保留草稿、标明失效、同时禁用 SDK/无障碍/可见控件，并提供显式重新绑定入口。实际指针选择、保存原值、失效与恢复分别验证；单纯直接写状态不能作为交互证据。

`App` 仅用于产品入口、`Plugin::build` 与 `install` 装配。截图安装器可注入隔离 adapter 和资源，但不能直接取出运行态业务资源；初始化也必须是受限参数系统。字体与图标资源在场景生成前初始化，缺少渲染资产的 headless 组合保留默认句柄；测试装配可以访问 World，以驱动真实系统和检验状态，不能由测试旁路代替生产实现。

## 1.2 WESL、GPU 资产与生命周期

以下要求适用于卡片、波形、二维拓扑、粒子、后处理与后续 3D；保留 CPU 回退和原有业务操作，不以 shader 文件存在代替实际管线交付。

### 源码与模块边界

- 项目自有 shader 统一使用 `.wesl`，入口只组织阶段输入、绑定与合成；uniform 类型、距离场、阴影、颜色或图形计算按职责拆到 `src/shaders/`，通过 WESL `import` 复用。禁止在 Rust 原始字符串里维护第二套 WGSL、运行时拼接模块或复制同一计算函数。WESL 最终生成 WGSL；上游 shader 的语言不由本项目强改。
- 包内导入使用 `package::…`，Bevy 类型从锁定版本的实际模块导入。嵌入路径、导入模块名、文件名和 `ShaderRef` 必须一致；新增依赖同时登记 embedded 资产与加载 owner。新增入口不能只改文件扩展名，必须在真实渲染组合下完成链接、验证和绘制。
- Rust 的 `ShaderType` 与 WESL uniform 类型共同构成 GPU ABI；字段顺序、类型、对齐、group/binding、顶点位置/颜色/UV location 必须同步修改。逻辑像素和物理像素只转换一次；颜色空间、直 alpha/预乘 alpha 及 blend 状态明确匹配，不以调色补偿错误合成。导数只在支持的片元阶段使用。
- 动态输入在提交前校验有限性、尺寸和适用圆角；零尺寸、无观测、负值、NaN gap 与不支持形状分别按既有语义回退，不向 shader 上传无效几何。SDF 近似不宣称精确距离或未经证明的 G2 连续性。
- `chart::mesh` 的 WESL 仍是未安装的遥测管线原型，接线须补 Mesh2d 视图变换、真实绑定与同样本对比。卡片入口为 `modern_surface.wesl`，计算模块归 `shaders/{surface_uniform,squircle,shadow}.wesl`；Rust 参数与材质归 `shader_fx`，受限同步归 `surface_shader`，加载归 `shader_assets`。

### Handle 所有权与复用

| 资源 | owner 与复用 | 退役与恢复 |
| --- | --- | --- |
| 字体、图标等共享只读资产 | App 级 `FontSources` / `IconSources`；实体克隆共享 handle，不逐行重复加载 | App 级资源有固定语义集合；实体退役只释放自己的引用，不删除公共资产 |
| 项目自有 WESL 计算模块 | `shader_assets` 的 App 级强 handle 集合；插件注册一次，在受限 `PreStartup` 加载一次 | 不调用 `mem::forget` / 泄漏 handle 固定存活；随 App owner 释放。锁定 Bevy 自身的常驻库计入框架基线，不能当作页面资源随意删除 |
| 波形、环图、直方图、二维拓扑的可写纹理 | 每个 chart entity 的 `chart::texture` 私有 owner；ImageNode 只是绑定，已有外部/图标 handle 不能被当作可写资产 | 数据、主题和尺寸变化更新原资产；仅实际资产缺失时创建替代。绑定丢失或被替换时优先重绑原 handle。移除绘制角色或销毁实体释放 owner |
| 卡片可写材质及未来可写 Mesh/后处理目标 | 每个可视对象或有界效果实例的明确 owner；材质 uniform/网格内容变化原位更新 | 卡片暂时零尺寸或形状不支持时解除绑定并保留每卡至多一个缓存，恢复复用；显式 Flat 关闭、移除角色及 despawn 释放引用。未来效果必须声明相同的停用和缓存上限 |

- `AssetId` 是身份而非保活引用；需要存活的 owner 持有强 handle。可写资产不作为任意实体间的共享写目标；绑定别人的 handle 不代表取得写入或删除所有权。共享只读引用不得阻止唯一 owner 原位更新自身资产，外部引用的作用与寿命必须明确。
- 每个图表根实体只挂载一种绘制 Plate，切换类型先退役旧角色。纹理 owner 同时记录绘制角色身份；同一实体从波形换成环图再恢复时，即使旧样本签名相同也须重绘正确内容，不能回放上一角色的像素。
- 禁止在每帧、主题切换或正常 resize 中重复 `Assets::add`；更新先比较实际内容，无变化不 `get_mut`、不光栅化、不产生上传事件。仅损坏/缺失资产允许新 handle，控件实体与草稿身份保持。
- 移除组件和 `despawn` 是两条独立退役路径，都要覆盖。生产系统通过受限 Query、Commands 与已声明的调度边界解绑并释放 owner，不遍历整个 World；不能仅因隐藏或页面变量变化就认为已销毁。
- 正常回收释放自身强引用，由 `AssetPlugin` 在调度中处理最后引用。禁止直接 `Assets::remove` 误伤其他持有者；底层 GPU 释放受 render world/驱动时序影响，资产表回到基线不等于已完成 Android 驱动显存实测。紧急设备丢失恢复仍由框架管理，业务不持有/手工销毁 swapchain。
- 缓存以实际 owner 和有限生命周期为边界。禁止无上限的全局 handle 表、Arc 循环、忘记释放的实体池槽或按 frame ID 追加素材；pipeline 变体键只含影响编译的有限配置，时间、节点 ID 和每次测量值不能生成新变体。

### 调度、回退与验证

- 卡片几何同步在实际 UI Layout 后执行；构造与退役通过 Commands 提交，输入树不随视觉刷新重建。动态效果只在可见、需要动画且用户策略允许时申请刷新，后台/减少动效/低电量/热状态按 Android 产品规范降级。关闭 Bloom 或 3D 要退役其目标纹理、Mesh、动画订阅及唤醒请求。
- 每项图形修改验证：静置无 asset Modified；同长度新样本正确更新；主题/尺寸更新保持 handle；绑定修复不重栅格化；共享外部资产内容和引用不受误伤；缺失资产恢复；组件移除、页面退役和显式关闭后资产数量回到基线。至少 100 次创建/销毁及回退循环，测试不得自己持有强 handle 后又要求其被自动回收。
- Rust 检查和 headless 测试不能验证 WESL 链接与 GPU ABI。实际 Vulkan 渲染验证双主题及桌面/窄视口，检查 shader/pipeline 错误并复核像素；Android 最终 APK 在目标设备验证 Vulkan/GLES 支持、帧耗时、native heap/GPU 内存及后台功耗，不从桌面截图推导。
- 结构检查、CPU 资产回收、GPU 绘制和 Android 长时资源报告分层登记；未接线的原型、设备未测的能力保留对应 TODO，不标整体完成。当前状态只归实际证据和 owner 台账。
- `scripts/quality/bevy_shader_guard.py` 在共享结构入口注册一次，阻断项目 `.wgsl`、Rust 内联原始 shader、显式泄漏、缺失/循环包内导入及未注册的 embedded 路径；规则夹具验证拒绝和放行边界。该守卫不编译 WESL、不判定 uniform ABI 或 handle 实际回收，后三者必须执行上述测试与渲染验收。

## 1.5 与 iced 的构建共存

bevy 栈与 iced 栈同 workspace 共存时会发生一次已知的 feature 统一冲突：bevy 的
`naga_oil` 打开共享 `codespan-reporting/termcolor`，破坏 naga 27（iced wgpu 27
依赖）的无 termcolor 诊断分支。现行修复：`infiltrator-iced` 持有改名直依赖
`naga27 = { package = "naga", version = "27", features = ["termcolor"] }`（仅
feature 用途，代码零导入）。iced 的 wgpu 栈升级越过 naga 27 后删除该条目。

## 2. crate 结构

| crate | 职责 | 依赖 |
| --- | --- | --- |
| `infiltrator-bevy-widgets` | 业务无关控件层：token/主题、排版角色、按钮、卡片、输入、滚动与菜单 | Bevy、Unicode 与共享本地化资源；无 application/宿主/内核 |
| `infiltrator-bevy-ui` | 前端壳：窗口组合（`DefaultPlugins`）、`ShellPlugin`、路由与页面；消费 contract/application 投影 | bevy + widgets + contract/application |

`WidgetsPlugin` 是唯一安装点：注入 `UiPalette` 资源、排版盖章观察者、控件换肤系统。
`ShellPlugin` 无窗口基础设施，`MinimalPlugins` 无头测试跑的是真实 shell。

## 3. 与 taskmanager 的控件抽取协议

两项目未来共同抽出业务无关控件层（"我们自己的 bevy_ui_widgets 皮肤包"）的判定
标准：**同一个控件在两个项目中第二次出现时，下沉**。为此：

- bevy 同锁 `=0.20.0-rc.2`；
- widgets 层零业务依赖、纯函数核可无头测试；
- 控件实现风格对齐（bsn! 场景函数 + typed marker 组件 + 观察者），搬运即迁移。

当前各自独立演化；BEVY-007 为正式评估项。

## 4. 当前实现与验证边界

默认桌面入口组合真实 `DesktopProductSession`、共享命令服务和完整页面 reader；演示必须显式选择。宿主初始化失败保持可见的类型化失败，不回退演示数据。控制器部分运行态与配置模型分开，配置必填字段不放宽，缺失观测不补为成功。

当前交互、像素、测试和缺口的唯一状态来源是 [UI_PARITY_AUDIT.md](UI_PARITY_AUDIT.md) 与 `scripts/parity/` 的实际解析报告。结构守卫与 headless 通过不能证明全部场景平权；历史截图、旧施工台账和单个架构编译结果不能代替当前完整验收。

Android 共享宿主交叉编译与 Bevy 移动产品宿主、APK 实际运行是不同证据。移动产品组合、平台包与真机/模拟器验收仍按 [PLATFORM_MATRIX.md](PLATFORM_MATRIX.md) 和实际产物推进。TalkBack 的上游能力边界保持明确，不把桌面无障碍证据外推到 Android。

Android 的进程所有权、原生输入、安全区、业务列表回收、数据唤醒与低功耗闭环统一遵循 [BEVY_ANDROID_PRODUCT.md](BEVY_ANDROID_PRODUCT.md)。已有页面、控件算法、共享异步桥接与二维图形继续保留扩展；宿主未组合和设备未验证分别补齐，不能通过缩减能力消除缺口。

## 5.5 0.30 大一统前端 15 项核心补强方案

0.30 Bevy UI 产品同时覆盖桌面（Windows/macOS/Linux）与移动端（Android），并与 Iced 保持同权交付。以下方案记录其原生实现路线，验收仍要求双端共享语义与适用的 L1/L2/L3 证据：

1. **BEVY-012 原生路由架构与 10+ 业务页面枚举**：
   扩展 `Route` 为 11 个全量业务页面枚举（`Overview`, `Proxies`, `Profiles`, `Rules`, `Connections`, `Logs`, `Dns`, `Doctor`, `AppRouting`, `Sync`, `Settings`）；统一走 `ContentSlot` 有界子树替换，保证幂等切换与零内存泄漏。
2. **BEVY-013 高性能无分配 Virtual List 状态机与视口物理回收**：
   复用 `visible_window_with_overscan`、动态行高、虚拟垫片与实体池，接入节点/网格、连接、日志和规则的真实页面。行根数量受视口与 overscan 约束，槽位复用核对稳定业务身份；完整数据与交互语义保留。实际帧耗时和内存按 Android 产品规范测量，算法存在不能证明实体回收已接通。
3. **BEVY-014 移动端响应式断点系统 (<600px) 与自适应双模外壳**：
   设立 `MOBILE_PX = 600.0` 与 `TABLET_PX = 1024.0` 响应式断点；在移动端 (<600px) 自动从桌面 240px 左侧 Rail 切换为「顶部状态栏 + 底部 Tab 导航栏 + 抽屉菜单」，并将触控热区由 36px 自动垫高至 48px 无障碍标准。
4. **BEVY-015 Android VpnService 宿主无感解耦适配器**：
   保留 shared `VpnServicePort`/`VpnServiceApplication`、Kotlin Builder/通知和 Rust tun2proxy；服务进程独立组合 application 与原生 bridge，经宿主 IPC 向 UI 提供 shared `StartVpn`/`StopVpn` 意图与快照。进程、FD、重启和 UI 退出所有权按 Android 产品规范实现；UniFFI/JNI 接缝本身不能证明已完成进程隔离。
5. **BEVY-016 动态图表自适应容器宽度与双曲线共用量程渲染**：
   废除硬编码 876px 宽度；改造 `ChartSpec` 支持百分比/弹性容器几何测量，并在上下行双曲线中引入统一动态最大量程归一化，解决上传下载量级悬殊时的视觉错位。
6. **BEVY-017 节点选择器网格/列表双模与低开销延迟着色**：
   迁移 Proxies 页面；支持 URLTest / Fallback / Selector 策略组折叠展开，支持按延迟高低三色染色（绿 <100ms / 橙 <300ms / 红超时），支持 Filter Alive 与拼音模糊匹配。
7. **BEVY-018 订阅流水线与配置聚合器页面投影**：
   迁移 Profiles 页面；展示订阅到期时间、剩余流量胶囊条、多订阅聚合合并开关，集成原子更新进度条与失败智能退避提示。
8. **BEVY-019 分流规则树与实时命中染色诊断器**：
   迁移 Rules 页面；展示 DOMAIN-SUFFIX, IP-CIDR, GEOIP, MRS 规则流，集成 Rule Tracer 模拟输入框，按真实规则树实时高亮匹配链路。
9. **BEVY-020 环形缓冲日志流与低开销正则高亮面板**：
   迁移 Logs 页面；对接底层的 500 条定长 RingBuffer，提供 DEBUG/INFO/WARN/ERROR 多级标签过滤与低开销关键词正则高亮。
10. **BEVY-021 实时连接审计与细粒度流阻断控制器**：
    迁移 Connections 页面；消费 WebSocket 连接快照流，富化 GeoIP/ASN 图标，支持按速率/总流量动态排序，支持单连接一键掐断与全量断开。
11. **BEVY-022 智能 DNS 解析与 Fake-IP 状态可视化**：
    迁移 DNS 页面；实时监控 DNS 解析延迟、Fake-IP 池占用率、DoT/DoH 状态，并主动告警 Android Private DNS 严格模式冲突。
12. **BEVY-023 系统自愈诊断与网络环境探活面板**：
    迁移 Doctor 页面；一键自检内核健康度、TUN 网卡分配、端口占用、DNS 污染及直连外网探活，提供一键自愈修复按钮。
13. **BEVY-024 进程级分流与应用代理多端交互卡片**：
    迁移 AppRouting 页面；桌面端枚举系统活动进程并提取应用图标，Android 端读取已安装 App 列表，以 Checkbox 矩阵精准下发分流白名单。
14. **BEVY-025 WebDAV 三向合并冲突解决器与同步面板**：
    迁移 Sync 页面；展示上次同步时间与代数（Generation），在配置冲突时提供 Local / Remote / Base 三栏差异并列比对与逐项合并。
15. **BEVY-026 全局模态弹窗、Toast 浮层与 AccessKit 语义全链路闭环**：
    实现基于 Scrim 遮罩的通用 Modal 弹窗系统与非阻塞 Toast 消息栈，每个新增控件与弹窗附带 AccessKit 语义节点。桌面与移动读屏分别以适用的实际平台证据验收；语义节点存在不代表 TalkBack 或 VoiceOver 已接通。

## 8. 进阶十五大维度演进与实事求是性能预算 (0.30+ / 1.0 终局路线)

为确保 Bevy UI 在超越传统桌面与移动端 UI 框架（Iced / Qt / Flutter / GPUI）的同时，**坚决不抛弃原生 GUI 的高效率、低内存占用与即时响应**，确立如下进阶十五大演进维度与**实事求是、严禁夸口**的性能指标红线。

### 8.1 进阶十五大演进维度

1. **渲染管线深度定制与计算着色器加速 (Compute & RenderGraph Shaders)**：SDF 矢量字形抗锯齿、物理拟真双重 Kawase 毛玻璃材质（GPU 后处理）、解析级圆角盒动态投影与 GPU Instancing 图元批量提交。
2. **声明式 UI 元编程与常量场景优化 (Const Scene Graph & Reactive DAG)**：静态场景编译期展平、细粒度反应式原子信号依赖拓扑、类型安全静态几何约束布局。
3. **自适应多窗口、画中画与工作区自由停靠 (Multi-Window, PiP & Workspace Docking)**：共享单个 ECS World 的跨原生 OS 窗口并发渲染、独立置顶桌面画中画网速浮窗、分栏工作区自由拖拽撕裂与吸附停靠。
4. **高性能 3D / 2.5D 全球网络拓扑与粒子引擎 (Spatial 2.5D/3D Globe & Particles)**：无缝桥接 Bevy 3D 渲染器嵌入交互式 3D 节点地球仪、实时数据包流向粒子物理模拟、UI 卡片视差微 3D 悬浮透视。
5. **移动端系统级深度集成与原生视图混排 (Mobile System Integration & Platform Views)**：Android TalkBack / iOS VoiceOver 原生无障碍桥接、摄像头扫码纹理 GPU 直通渲染、移动端抛掷惯性滚动物理引擎。
6. **多模态音效与触觉物理微反馈系统 (Audio-Haptic Multimodal Feedback)**：微触觉波形（Android Vibrator / iOS Haptic / macOS 触控板）、程序化零延迟 UI 微音效、手势速度加权振动阻尼。
7. **智能网络上下文感知与预测式 UI 预取 (Smart Context Sensing & Predictive UI)**：启发式最佳节点智能评估与高亮、网络故障交互式自愈向导卡片、异常流量热力图视觉警示。
8. **动态着色器皮肤、主题热插拔与视觉沙盒 (Shader Skins & OKLCH Palette)**：运行时 WGSL 动态热重载、基于色彩科学的 OKLCH 感知均匀色阶生成、主题 Token 跨端标准 JSON/Tailwind 互转。
9. **富文本高级排版、双向文字 (BiDi) 与数学公式 (Advanced Typography & BiDi)**：OpenType 连字与可变字重无级插值、阿拉伯语/希伯来语 RTL 布局镜像翻转、轻量级 Markdown 与行内指标胶囊混排。
10. **高性能本地嵌入式时序数据库与时空回放 (Embedded TSDB & Time-Travel Replay)**：SIMD 加速时序存储与动态重采样、时间轴滑动条历史网络状态时空回放、多维交叉透视统计图表。
11. **WASM / QuickJS 驱动的微前端插件 UI 沙盒 (Micro-Frontend Widget Sandbox)**：轻量级自定义仪表盘小组件沙盒、声明式受限 UI 渲染槽、社区扩展市场与可视化安装器。
12. **电视大屏 (10-Foot UI)、手柄与全模态控制体系 (10-Foot TV & Gamepad Engine)**：Android TV 十字键导航、游戏手柄左摇杆平滑阻尼滚动、局域网 mDNS 跨端伴侣控制屏幕。
13. **极限冷启动预热、零开销内存与二进制瘦身 (Sub-Millisecond Boot & Optimization)**：管线与布局缓存静态预编译消除首帧卡顿、只读数据段 mmap 零堆分配启动、PGO 引导编译与符号剥离。
14. **全场景数字孪生仿真、网络混沌工程与压力测试 (Digital Twin & Chaos Sandbox)**：网络故障注入沙盒（突发丢包/高抖动/DNS污染）、全自动无头 Monkey 探索机器人、云端真机自动化性能与视觉基准流水线。
15. **跨项目通用 GUI 框架独立抽取与生态标准化 (Universal Widget Engine Extraction)**：纯净通用控件库独立 Crate 抽取发布、跨项目统一 ABI 规范、多平台宿主薄壳标准化模板。

### 8.3 收放自如的降级原则

1. **可有可无**：高级特性（3D/粒子/毛玻璃/TSDB/WASM 沙盒）全部由 Feature Gate 控制编译，运行时默认关闭或按需初始化。
2. **随用随清**：大显存纹理与 3D 资源仅在特定页面激活，离开视口 30s 即刻 Drop 释放显存，禁止无限制常驻。
3. **能耗优先**：感知低电量模式或系统发热时，自动降级至 Eco 档位，保全核心代理与交互流畅度。
