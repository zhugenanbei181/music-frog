# 代码质量规范与工程底线

> 层级：L2

本文件规定全仓代码质量底线。产品语义与双端交付规则分别由 [ARCHITECTURE.md](ARCHITECTURE.md) 和 [UI_PARITY_AUDIT.md](UI_PARITY_AUDIT.md) 负责；结构门禁不能替代行为测试或像素实证。

## 文件与职责

- 每个 Rust 文件最多 800 个非注释、非空代码行。生产源码、集成测试、路径挂载测试、示例和构建辅助代码使用同一预算；测试没有豁免。
- 拆分按业务职责、状态模型、场景构造、交互系统或行为契约进行。父模块承担组合与共享支持，不继续堆积新用例。
- 禁止压行、多语句合并、提高阈值、白名单、把代码放入注释或用 `include!` 拼接源码规避预算。嵌入字体/资源/fixture 的 `include_bytes!`、`include_str!` 不属于源码拼接。
- 拆分与格式化必须保留资源和测试夹具的字节内容，尤其是 raw string 内部的 YAML/JSON 缩进；不能对整段源码逐行去缩进。
- 函数与类型保持单一职责；拆分后仍有唯一 owner。不得制造空挂路由、占位表面或只为过门禁增加转发层。
- 行数事实由 `scripts/quality/line-guard.py` 的固定上限负责，新增或修改文件必须通过全仓检查。

## 导入与唯一类型定义

- 类型、trait、函数、宏和常量从定义模块明确 `use` 导入。相同定义模块的导入合并为清楚的导入组。
- 函数体、字段、签名、泛型、场景模板中禁止用 `crate::a::b::Type`、`infiltrator_x::a::Type` 等内联长路径替代导入。文档、资源字符串和导入声明不属于代码引用。
- 普通引用使用导入名；确实同名时导入其定义模块，使用简短的 `module::Type` / `module::function`。保留库入口的简短命名空间和标准属性写法，不通过引入整个 crate 伪装长路径治理。
- 禁止命名导入别名 `use ... as Name`；匿名 trait 导入 `as _` 保持原有允许范围。
- 禁止 `pub use`、`pub(crate) use` 和纯 `pub type` 类型转发。模块直接暴露定义，调用方从定义模块导入，不能用第二条类型路径绕过禁止 re-export 的规则。
- 组合类型、原始标量的语义类型别名、平台实现选择与既有 HTTP 依赖版本收敛不是数据模型转发。既有 FFI/依赖收敛边界以架构文档和门禁登记为准，不为业务便利新增例外。
- 重整导入时保持条件编译、类型身份与名称冲突语义；不能删除其他平台的导入来消除本机警告。

## 架构与界面

- domain/contract/ports/application/composition 保持前端中性；不依赖具体 UI crate，不按前端身份编译。
- UI 提交 typed 意图、消费投影，业务折叠在唯一 domain/application/projection owner 完成。Iced 使用 TEA，Bevy 使用 ECS、`bsn!` 与 Observer。共享 reader 与用例入口也不得各写一份排序、过滤或状态推导。
- Bevy 生产代码禁止接收或透传整个 `World`，不得用独占系统修补业务调度，也不得通过 `App::world()` / `world_mut()` 或 `DeferredWorld` 包装绕开；插件装配同样不豁免。使用最小 `Query`/资源/事件参数与职责明确的 `SystemParam`，字体与图标在受限 `PreStartup` 系统初始化，实体生命周期通过系统顺序和 `ApplyDeferred` 闭合；框架接线边界与结构门禁见 [BEVY_UI_FRONTEND.md](bevy-ui/BEVY_UI_FRONTEND.md)。
- Bevy 页面根组件不以 `on_insert` hook 注册业务观察者或重置资源。页面插件一次装配，路由只管理实体生命周期；草稿、分页与 Tab 状态遵循各自 owner 的状态机。控件初始化使用受限 `On<Insert<T>>` Observer，生产源码禁止 `DeferredWorld` 参数、字段和包装器。
- Bevy 查询与系统参数不能以 `allow(clippy::type_complexity)` / `allow(clippy::too_many_arguments)` 消音。复杂访问使用实际 `QueryData` / `QueryFilter`，相关原生控件目标按一个交互或投影职责组合 `SystemParam`；资源、事实与业务模型仍由唯一 owner 持有，不能把整个页面状态或跨页面服务塞入参数对象。互斥筛选和 `ParamSet` 的访问顺序必须完整保留。
- 外壳计数、活动配置、配额和速率只回放共享 application 的不可变投影；禁止固定示例数字或在 UI 缓存中重新汇总。完整数据量与显示窗口分开，未观测、真实零值和已失效观测不能混同；失败保留上次真实值，配置/会话变化不能复用另一对象的数据。原生波形只回放共享样本，不生成装饰性流量柱。
- 偏好、控制器运行配置与生命周期是独立观测。设置页读取成功不能证明 TUN、模式、端口或 LAN 已被观测；缺失模式不能补为 Rule，任意 Overview 数据不能证明脚本能力。运行控制使用可选事实与 typed 读取状态，失败保留旧值并阻断动作，切换代次清理旧观测；命令回执保留 Failure 类别，不降为字符串。
- 观测保留必须在界面标记失效，不能仅禁用按钮却继续显示为当前成功状态。写入等待使用共享状态文案，回执不能替代读回；原生模式选择、状态灯和无障碍禁用状态需以实际控件事件与生命周期回归验证。
- 控制器响应类型不得用配置默认值抹掉字段存在性。可缺失的 IPv6、LAN 安全与 TUN 子字段使用 `Option`，必需的运行态字段缺失时解码失败；显式 `false`、空列表和零值仍保留为实际报告。验证写入缺少目标字段时返回 typed 未验证，禁止把缺失读回当作请求值已生效。Iced 不再持有另一份将缺失字段折为布尔值的运行配置 DTO。
- 存活、可用与是否已观测必须来自真实事实源；历史延迟不能代替当前健康标志，缺失标志保持未知。筛选不修改内核当前选择；新增对象按共享默认状态出现，不能继承另一端的白名单模型。
- 两端生产 UI 与控件层的全部文案只从共享本地化资源读取，禁止裸中文文案与第二套翻译表。遗留字面量同样由门禁阻断，不以“旧代码”或“演示页面”豁免；测试夹具、地区识别词典与用户数据按其真实职责处理，不能将文案改成 Unicode 转义规避扫描。
- 错误说明、恢复建议、通知与无障碍提示同样进入共享语言资源表；错误码到资源键的映射保持类型化，不能在业务或 UI 中维护另一套按语言分支的翻译。中英文模板的参数集合必须一致，重命名或遗漏参数由结构门阻断；结构门不能证明运行态错误已全部完成迁移。
- 产品自身的错误原因通过中性 `FailureReason` 携带结构化参数，由 `application::failure_projection` 映射共享语言资源；不能在用例中预先拼接中文或英文，再让另一端原样显示。外部解析器与宿主诊断作为不透明明细保留，禁止按已渲染错误字符串反查类型或翻译；新原因必须覆盖两种语言及实际失败路径。
- i18n 结构扫描必须覆盖 UI update、状态与视图；仅扫描视图会遗漏通知与异步失败路径。取消等业务分类必须来自 typed 结果，禁止通过匹配中文或英文错误正文识别。后端通知也复用共享资源，结构扫描范围外的遗留项继续按实际行为迁移，不作为豁免。
- `infiltrator-shared` 是产品文案唯一资源源；静态标签声明共享键，动态语义文案由 application/projection 统一折叠并使用共享单次插值。禁止各端独立翻译、按已渲染文本反查键或复用语义不同的操作键。演示身份来自共享隔离夹具，不将真实用户数据翻译成文案。语言切换更新原生实体与无障碍标签，不重建交互控件。
- 语言切换原位更新文本、占位提示和无障碍标签，保留焦点、输入草稿、选择、当前分页与正在运行的状态。动态文案必须更新键与参数；不能重新显示旧占位内容。插值只解析一次模板，不重新解释用户数据中的花括号。
- 禁用中断按压必须清理 SDK Pressed 状态，恢复后旧指针点击不能重放操作；测试使用真实 SDK 按压与点击事件。
- 禁用必须同时进入原生 SDK 交互标记、无障碍状态与可见色阶；仅在提交 handler 中提前返回或只保存产品 bool 不构成完整的禁用控件。状态恢复同步解除三者，保留原生控件身份与焦点。
- 控件交互状态同步与实体退役必须在同一有效生命周期内完成；禁止让 SDK 状态写入排队后落到已删除实体。按压取消、禁用与无障碍更新使用当前实体代次，实际渲染与同帧退役测试均须通过；不得消音队列错误掩盖生命周期缺陷。
- 原生控件的本地化键必须随场景附着到真实控件根节点和文本节点；工具包接受声明式标签场景，不能在刷新时按已渲染字符串反查翻译键。文本输入创建时具备 TextInput 无障碍角色，语言变化同步标签与占位提示。
- 草稿控件必须接收原生 SDK 输入事件并更新真正的编辑状态。测试不能只直接写入 `Checked`、文本或状态变量来证明用户交互；修改草稿不提交持久化命令，实际预览或应用读取最新选择。
- 用户表面只保留操作所需的信息；源码模块名、用例名、台账编号与后续版本施工承诺放在工程文档，不作为正常页面文案。
- 快速输入保留最新草稿，共享偏好命令按用户输入顺序串行提交；过期终态不得覆盖新草稿，也不能让较早查询最后写回事实源。
- 动态列表必须覆盖从非空到空再恢复；ECS 空容器可能没有 `Children` 组件，不能因此丢失新增内容。
- 读取失败或加载中不能当成空结果、节点删除或偏好默认值。保留最后一次真实观测并显示失效状态，禁用依赖当前观测的操作；只有成功的新观测才能证明删除。共享 reader 保留错误类别和恢复策略，不把所有失败改成网络错误。
- 文档、选项与来源核验具有独立读取状态；列表失败不能移除编辑器观测，选项读取成功不能清除文档读取失败。编辑保存需同时满足当前来源核验和对应读取成功；迟到读取、失败与加载标记都核对同一产品、配置代次和请求身份。配额旧值保留还须确认相同订阅来源，不向界面泄露订阅凭据。
- 原生模态必须隔离背景输入。遮罩消费点击与滚动，内部控件正常处理事件；取消与隐藏不能触发下层选择、探测或其它业务写入。
- 渲染缓存依据完整内容或明确版本刷新，不能只比较集合长度。持久选择绑定稳定对象 ID；重排继续检查原对象，删除后关闭并拒绝过期操作。
- 规则草稿行操作携带共享 owner 分配的稳定行 ID，不携带显示索引。重复表达式仍为独立行；重排、新增保留原行身份，删除、取消草稿与源切换退役旧身份。排队的原生输入必须拒绝已退役控件，不能误改占据同一索引的新行。
- ECS 控件必须在创建时具备必需组件，使用原生 required components；不能依赖下一帧补挂命中组件。活跃表面的事实刷新保留控件与纹理实体，不重建整棵树打断输入或制造过期命令。
- 声明滚动布局必须同时接入工具包的实际输入行为；仅有 `overflow` 或视觉滚动样式不能证明内容可达。
- 两端都必须拥有等价的操作深度。模态、抽屉、向导、检查器不能退化为 Toast、静默执行或空页面。
- 独立产品默认入口必须组合真实宿主、命令服务与完整页面 reader。演示只能显式选择；初始化失败、端口缺失或 handler 缺失必须返回实际失败，不能回退为演示数据或无作用的成功回执。
- 不支持、权限不足、失败、取消、空态和真实零值必须区分。速率等派生指标保留采样是否成立，不能凭数值大于零判断是否存在观测。未验证的行为、平台和像素不能写成已验证。
- 异步操作必须按请求身份接收终态结果；队列接受、内存变换或投影刷新不能代替持久化成功。保存失败保留编辑表面与草稿；只有事务成功后才发布“已保存”事实。
- 配置编辑请求绑定实际源文档身份与已观测的原始内容。事务校验后固定对应文档路径，不通过再次读取当前配置把已确认内容写到另一文件；源变化拒绝提交，回滚恢复该次事务实际确认的旧内容。
- 配置与选项的来源比较、持久化发布必须处于同一个 adapter 写入边界，普通保存、选项保存及删除也参与该边界。同一目录的独立 manager 不能各自创建互不相干的锁。持久化锁不得跨越可能保存配置的生命周期回调；失败回滚须重新确认该次写入仍有效，不能覆盖后续编辑。进程内锁不构成进程间或断电恢复证据，文件事务也不证明运行内核已应用。
- 可选存储文档只有 `NotFound` 可折为缺省值；权限、无效编码、解析和其它 I/O 失败必须保留为类型化错误。空值删除同样只忽略不存在，不能吞掉删除失败。整份文档发布使用写入者独占的临时文件、完整写入与 flush/sync 后替换，不共用固定临时路径，也不先删除目标文件。整份文件替换不等于跨文档事务或来源比较提交，不能据此宣称配置及选项已原子闭合。
- 语言偏好必须保留系统、简体中文、英语三个类型化选择，由共享设置 owner 保存；解析失败不得默认落到中文。持久化失败保留当前语言与待重试选择，成功终态才应用，旧快照不得撤销新选择。语言变更原位更新文案、标签和占位符，保留原生输入实体、焦点、选区、草稿与 IME；普通设置保存不得将系统偏好覆写为当前解析语言。
- 诊断状态保持 Pass/Warn/Fail/Skip 四种类型化事实，未知状态必须拒绝；跳过、未运行与空报告不能判定为健康。命令服务与页面 reader 共享唯一报告 owner，修复和初始化完成后重新读取实际结果；失败与取消保留上一份报告并显示失效状态。列表操作绑定稳定检查 ID，过期观测禁用修复，待完成回执不能当作成功。
- 批量操作必须检查每个实际执行结果。部分或全部失败不能发布无条件成功；保持原始错误类别与重试策略，明确失败数量。不能为避免报错提前丢弃失败项或将未观测的结果补成成功。
- 控制器运行态与配置结构分开：兼容部分报告不能把配置必填字段改成默认值，更不能合成服务器、端口或凭据。已报告的非法字段必须拒绝；缺失观测保持未知。
- HTTP 请求发送完成不等于服务端接受。所有控制器读写核验状态码，认证、权限、非法参数和网络错误保持类型与恢复策略；旧失败不能变成成功回执。
- 参数编辑必须保持草稿与已保存值分离。所有实际执行入口读取同一份已保存参数并使用共享校验，不静默截断非法值；取消不写入，保存中禁用输入与重复提交，失败保留草稿供重试。
- 数值来源必须明确。历史零延迟未提供逐条结果，不能判定超时；独立测量的真实零值、未判定零值与未观测须分开。语义色阶与标签折叠共享，原生层只选择对应样式。
- 命令终态用 `Result<(), Failure>` 或等价类型化枚举表达，禁止成功布尔值与可选错误并存产生矛盾状态。内核启停必须核对真实生命周期，失败不得显示已停止；等待期间禁止重复提交，旧请求回执不能解锁新请求。停止内核不销毁产品宿主与页面 reader。
- 带业务结果的命令使用中性类型化输出，贯穿请求身份、源身份与真实统计。无结果成功不能替代过滤报告等必需输出，读取共享缓存不能冒充该请求的返回值；错误类型和缺少终态明确失败。两端从组合根注入的应用边界提交，不在 UI 内为单个业务临时构造具体宿主服务。
- 控制写入与轮询读取分别关联请求身份和读取边界。写入前、写入中的旧读取不能撤销该次已验证的控制器回执；新鲜读取可反映实际外部变化。写入失败保留类型与恢复策略，健康读取不能自动清除错误操作面，也不能改变实际生命周期。
- 复合事务不得重复获取自身已持有的异步串行门；业务命令与内部生命周期操作使用明确的层级。关闭产品必须拒绝新请求、完成当前事务、解除所有权环并停止内核，不能在退出后执行排队的启动操作。
- 实时流的接收、容量、身份与故障保留由共享 application owner 管理；同一会话的失败保留实际记录，新代次与新 token 阻断迟到事件。日志级别来自报告元数据，不由正文中的 ERROR/WARN 等单词推断，不将未知补为 INFO。连接建立和重试等待也参与取消，关闭必须释放消费者与后台驱动。
- 原生操作必须有真实作用与结果边界。复制按钮写入平台剪贴板；缺失或失败明确呈现，不能先发成功提示，也不能把进程内缓冲当作系统剪贴板。

## 验证与反规避

- 结构检查、真实测试发现、测试实际执行、场景交互、像素回执是不同证据层，分别负责自身事实。
- 空态测试必须明确构造空输入，不能借适配器丢弃数据制造空态；路由测试同时核对真实挂载页面，不能只检查路由变量。
- 禁止用硬编码通过的能力报告或测试调用同一报告再次断言通过来冒充回归证据。真正的用例必须执行对应行为；无实际观测的汇总不产生成功事实，历史假报告应退役并纠正台账。
- 不以类型名、函数名、断言数量或 `assert_eq!` 比例证明行为质量。测试应验证明确的结果、状态转移、取消无副作用、错误恢复与身份/代次不变量。
- 系统子进程等夹具使用作用域回收，无论断言成败均终止并回收自身创建的资源；不放宽进程身份校验以换取通过。
- 定时与调度测试使用虚拟时钟或显式事件同步；不以极短墙钟 sleep 假设任务已经执行。
- 不删除断言、降低门禁、提高预算、静默跳过失败测试或增加消音属性来获得绿灯。合理的框架约束必须有具体原因，不作为掩盖设计债务的通道。
- 使用 nextest 运行 mock/headless 测试。导入/文件重整必须核对测试发现数量、修复真实测试 ID 绑定，并通过全仓测试、fmt 和 clippy；不把改名后的悬空锚点登记为完成。
- UI 变更必须通过适用的双端交互与真实像素验收。原生控件布局查询确认交互区域可见，再核验区域自身的像素；整页非空不能证明模态或节点可达。回执绑定归档产品产物，完整性与变更影响分开；相关编译输入/运行资源变化触发复验评估，无关改动不能把已通过验收归零。发布按显式候选构建 ID 验收，不能混用不同构建的像素；具体规则见 [UI_PARITY_AUDIT.md](UI_PARITY_AUDIT.md)。
- 列表编辑场景同时核验实际业务行及保存/取消或恢复操作面。标题、状态说明、预览摘要和保存栏不能代替列表；可观测规则行不存在、被无关面板推到不可见区域或被布局压成空白时，场景回执必须失败。虚拟列表保留共享窗口与稳定行身份，首屏先呈现列表，构建器和统计通过原生滚动访问。
- 行根边界合格不能代替内容可读。紧凑布局同时检查编号、类型、正文和目标等关键原生文本的独立边界，保证完整可见且不重叠；操作区保持可达。真实图像发现问题时，机器通过的回执仍须退役，修复并以新源码重新取证。
- 构建 view、更新投影或几何查询通过不能发布“已渲染”标记。Iced 场景取证等待实际 redraw 并读取原生 GPU 帧，合成器截图必须与同次原生帧的交互区域像素一致；原生帧路径、哈希和比较结果进入回执。只用固定延时、非空页面或旧帧通过验收均属无效证据。
- 发布包必须携带匹配架构的锁定内核、许可与来源信息；压缩包和解压字节分别校验，未知版本或目标 fail-closed。运行副本按内容身份更新，损坏缓存必须修复；包模板通过不能替代实际编译、展开与文件哈希核对。
- 正式发布必须通过全量双端场景验收。`release.yml` 的平台构建依赖 `parity.yml` 对 `FeatureId::ALL` 执行真实行为与两种视口像素验证；部分场景通过、静态页面截图或历史回执不能放行版本。

执行入口是 `bash scripts/test.sh`、`bash scripts/test-bevy.sh` 与 `scripts/parity/`。共享结构检查只在 `scripts/quality/check-structure.sh` 注册一次。

- 演示值只能由显式隔离的 fixture 提供。生产操作不得给配额、延迟样本或事务成功写入固定值；选择、导航、打开和关闭表面不会生成测量或持久化回执。配额的缺失、真实零和溢出分别处理；原生进度几何按共享实际比例回放。已有共享观测或交互 owner 必须复用，禁止保留第二份 UI 状态作为业务事实。
