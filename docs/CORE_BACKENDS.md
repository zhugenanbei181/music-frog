# Core 后端契约

> 层级：L2

Mihomo 与 sing-box 均已有 production backend provider。Desktop `DesktopProductSession` 按持久化 active-profile reference 选择 engine-keyed provider：Mihomo 使用 `PreferBundled`，sing-box 只接受已管理且有匹配验证证据的二进制。`DesktopProductSession::switch_engine_profile` 已接入共享 durable owner-switch transaction；Mihomo 重新组合完整 Desktop runtime，sing-box 保持 Core lifecycle-only。Android `:vpn` 也已按同一 revisioned active-profile reference dispatch Mihomo 或 sing-box：sing-box 路径创建 engine-scoped JSON profile store，要求精确 Android ABI 的 managed binary 与验证证据，并由 Rust `SingBoxCommandPort::check_config` 在签发 typed launch spec 前校验 profile。Kotlin host 在 spawn 前再次核对 document revision、安装回执、目标 ABI 和二进制摘要，再通过 owner context 记录 child process。Android `:vpn` 的 engine-keyed version registry 现由一个 `CoreVersionManagementApplication` 持有；既有 sing-box `RollbackCore` 与 `CheckUpdates` 的 `VersionApplication`、settings store 和 binary-selection port 从这一 registry 解析。共享 application 已实现异步安装任务的 typed ID、进度、取消请求和终态管理并通过 fake/nextest 覆盖，但新的版本管理 IPC 尚未接入；安装、激活、卸载、运行态 profile apply、overview/runtime 操作和运行中 profile switch 仍未接入。Android `:core-host-tests:test` 为 44/44，Rust Android nextest run `f8b60238-71ce-4c8b-8183-32bf21b7fa05` 为 145/145；此前 contract/sing-box/Android Core nextest `b35b1919-cd74-46bb-91cb-9177cc67f993` 为 538/538、1 skipped。当前没有 Android target build、APK、设备进程或双引擎流量证据，不能宣称 Android 双引擎产品验收完成。Desktop session handoff 的 typed failure fake 覆盖已通过；候选运行时组装失败注入、真实 Desktop 双引擎切换及 Android owner/service 真机验收仍开放。引擎 adapter 的存在不代表全部操作可用：能力仍按 operation 与证据 fail closed。新增 adapter 必须实现此中性契约并完成真实二进制验收。资产与平台状态见 [PLATFORM_MATRIX.md](PLATFORM_MATRIX.md)。

## Adapter crate owner

每个引擎都按稳定职责边界拆包；能力尚未验证的操作仍在所属 adapter 中返回 typed `Unsupported`，不能因此把多个职责并回一个 engine umbrella crate。

| owner | Mihomo | sing-box | 边界 |
| --- | --- | --- | --- |
| Controller API | [`mihomo-api`](../crates/mihomo-api/README.md) | [`singbox-api`](../crates/singbox-api/README.md) | HTTP/WebSocket、engine wire DTO、readiness、运行态映射与 operation evidence |
| Native configuration | [`mihomo-config`](../crates/mihomo-config/README.md) | [`singbox-config`](../crates/singbox-config/README.md) | 原生格式 codec、校验和 engine-specific 配置事务；不拥有通用 profile 文件协议 |
| Core process | [`mihomo-process`](../crates/mihomo-process/README.md) | [`singbox-process`](../crates/singbox-process/README.md) | engine-specific command、spawn/stop 与生命周期 adapter |
| Version assets | [`mihomo-version`](../crates/mihomo-version/README.md) | [`singbox-version`](../crates/singbox-version/README.md) | 发行资产锁、验证、安装、激活、卸载与回滚 |
| Shared profile persistence | [`ProfileStore` port](../crates/infiltrator-ports/src/profile_store.rs) | 同一 port | `infiltrator-profile-store` 拥有 engine-scoped document/sidecar、workspace、catalog 和 aggregation-template 文件机制；`ConfigManager` 暂仍实现 port 并协调 selection/owner transaction lease、namespace migration 与 active owner transition，CORE-018.3 继续收口 |
| Shared host capabilities | [`infiltrator-platform`](../crates/infiltrator-platform/README.md) | 同一 owner | 路径、凭据、安全文件替换、Android owner bridge、网络/电源等 OS 能力 |

依赖只向 engine-neutral ports/contracts 汇聚，再由 composition 装配需要的职责包。各 adapter 不得通过跨引擎 adapter 依赖共享事实：

```text
contract + ports
       ↑
 shared profile store / shared platform     mihomo-* adapters     singbox-* adapters
                  \                              |                    /
                   └──────────────── composition ─┘
```

`mihomo-dav-sync` 仍是 Mihomo YAML profile sync owner：其 indexer 只选择 YAML 文件，冲突算法解析并合并 YAML。若改为原样同步任意 `ProfileDocument`，应先迁移到 engine-neutral sync contract，再调整名称。

## Backend-neutral adapter contract

[`EngineBackendProvider`](../crates/infiltrator-ports/src/engine_backend_factory.rs) 是 Mihomo 与 sing-box 共用的 backend adapter trait。它按 `EngineId` 生成同一形状的 [`EngineBackendPorts`](../crates/infiltrator-ports/src/engine_backend_factory.rs)：统一承载 Core process/readiness、document inspection、native configuration transaction binding，以及有明确 `Available`/`Unsupported` 状态的 outbound/routing ports。Composition 和 conformance 都通过该契约选择 backend；引擎差异留在各自的 process、config 与 controller API owner。

版本发布和操作能力继续使用 [`EngineVersionBackendFactory`](../crates/infiltrator-ports/src/engine_version_backend_factory.rs) 与 [`CoreCapabilityProvider`](../crates/infiltrator-ports/src/core_capability_provider.rs)，并以同一 `EngineId` 关联到 backend。这样共用启动、配置、作用域和能力授权流程，同时保留 Mihomo YAML/REST/release identity 与 sing-box JSON/Clash API/release lock 的原生语义。产品接线按宿主可用能力注册；缺少组件时返回 typed `Unsupported`，不能从另一引擎复制能力声明。

- Profile 绑定 `EngineId`；命令、回执与快照绑定 `CoreScope`，身份或代次不符时拒绝更新。
- 能力按 operation、engine/version、host、binary target 和 adapter revision 查询；需要活动版本的引擎操作必须匹配精确版本/目标/revision 证据，无活动版本的引擎操作仍须匹配目标/revision 的操作证据。[`CoreBinarySelection`](../crates/infiltrator-ports/src/core_binary_selection.rs) 携带所选 executable 的 `EngineBinaryTarget`，产品根在构造 backend 前通过 `validate_for` 校验 engine 与当前 host target；target 事实与 version/provenance verification 分开校验，任一不匹配都 fail closed。缺少能力、证据或 owner-composed port 时 fail closed；进程运行不代表代理/VPN 已生效。
- Core version management 的共享 capability enum 明确区分 `Inspect`、`Install`、`Activate`、`Uninstall`、`Rollback`，都不要求活动 Core 版本并归属 typed `VersionManagement` owner。产品接线未完成的操作继续声明 `Unsupported`；引擎存在 VersionPort 不等于产品已开放该操作。
- 每个 owner process 恰有一个 Core actor。
- [`CoreProcess::start`](../crates/infiltrator-ports/src/core_process.rs) 必须携带显式 `CoreProcessStartContext::{Managed, Standalone}`；`Managed` 携带 identity/generation/session，Android 只接受该变体，并只将同一上下文的运行子进程作为重复启动确认。`CoreApplication` 先调用 typed `prepare_start` admission，再通过 owner lease 持久化 exact `Managed` context，之后才允许 spawn；Android 对 foreign/running、exited-awaiting-recovery 与 unavailable observation 分别 fail closed。owner proof schema v2 持有该 launch context；v1 bound 记录迁移为 `LegacyUnverified`，不授权自动恢复。Android `:vpn` host 在 spawn 前原子写入 launch reservation，spawn 后原子记录 managed context、PID 和 `/proc/<pid>/stat` start ticks；owner 重启后只有精确身份仍运行才恢复为 `Running`，PID 复用、损坏记录、无法唯一识别新 child 或不可读 `/proc` 都 fail closed。PID 通过 ProcessBuilder 调用线程的 `/proc/<pid>/task/<tid>/children` 前后差集采集，以兼容低于 Android API 37.2 的设备。新 `:vpn` session 通过 [`AndroidCoreOwnerRecoveryApplication`](../crates/infiltrator-application/src/android_core_owner_recovery_application.rs) 先读取 child observation，拒绝仍运行或不可观测的 child，再要求 VPN stop terminal readback；对精确 Exited Managed context 恢复持久 owner proof 后才消费 child record，随后才迁移 legacy selection 并开放 provider binding。Rust owner phase 使用 `Uninitialized/Recovering/Ready/Active/Closing/Closed` typed states；只有完成 recovery 才进入 `Ready`，所有直接 SharedCore ingress 在此前 fail closed。Kotlin `Preparing/Active` owner-session gate 允许准备阶段发布 VPN 快照，但只在 recovery 完成后读取 Core，避免 startup 重入。`:core-host-tests` 与 Rust nextest 覆盖 typed fake/JVM 路径；这些自动证据不证明目标设备 `/proc` 权限、`:vpn` service death/rebind 与真实子进程行为。
- [`CoreProcess::stop`](../crates/infiltrator-ports/src/core_process.rs) 成功必须证明该 Core 进程实例已退出；收到 kill 请求或 PID 记录缺失都不构成终态。桌面 adapter 校验 PID 对应的二进制并有界等待退出，Android host 返回等待退出后的 typed receipt。`CoreApplication::close` 仅在 `Stopped`、无 session 且 owner identity/generation 匹配后释放 owner。
- Android owner shutdown 由 [`CoreOwnerShutdownApplication`](../crates/infiltrator-application/src/core_owner_shutdown_application.rs) 按 VPN terminal readback → Core close/readback 顺序执行；任一步缺少终态都保留 owner fence，不能先停 Core 后把 VPN/数据面留在活动态。
- `doctor run` 是只读观察：版本检查通过 typed observation 读取已选版本和二进制，也可观察旧版版本目录，不创建或迁移版本 namespace；所有修复只由显式 `doctor fix` action 执行。实现细节见 [mihomo-version 说明](../crates/mihomo-version/README.md)。
- 产品级 Core provider 由持久化的 revision-fenced `ActiveProfileReference::{Unselected, Selected}` 唯一选择，`Selected` 同时携带 `engine_id` 与 `profile_id`。组合层必须在 provider dispatch 前读取该引用、加载精确 `ProfileDocument` 并校验其 engine/profile identity 与目标 capability；每 engine namespace 的 current pointer 不具备跨 engine 选择权。读取是只读快照，选择写入使用跨进程 revision CAS 与 OS 锁。owner guard 绑定到 `CoreApplication`，只有成功关闭后才释放；稳定 owner identity 使用 engine+instance，runtime version 是可变 capability evidence；generation、terminal 状态、session 与 owner token 仍精确校验。若新 owner 的宿主构造在 `CoreApplication` 创建前失败，必须显式中止候选 reservation；创建后失败则必须关闭应用并验证精确 terminal readback。共享 typed owner-switch selector 事务及候选释放行为已有 fake/nextest 覆盖；switch 调用必须携带构造目标 provider 时所依据的精确 `ProfileDocument`，selector 在旧 owner close 前比对，并在关闭前再次读回目标文档。失败回执区分 `BeforeReservation`、`ReservationPending`、`OwnerTerminationUnconfirmed` 和 `OldOwnerClosed`，调用方据此保留旧 session、进入恢复态或要求新 session。Desktop 初始产品会话与跨引擎切换现已使用 engine-keyed provider；产品 session 通过显式 `Open/Switching/RecoveryRequired/Closed` 状态封装 owner handoff。Mihomo 切换重新组合完整 Desktop runtime；sing-box 当前只暴露 Core lifecycle，其它操作保持 Unsupported。切换路径的产品级失败注入、目标版本真实双引擎进程验收仍开放；Android `:vpn` 双引擎接入也未完成。版本 factory 已 engine-keyed；sing-box target/revision-locked version factory 用于 Desktop 受管二进制选择，版本管理操作的产品接线仍未完成。
- 活动 profile 的内容修改使用 revision-bound `ActiveProfileWorkspaceWriteLease`：同一 lease 持有 reference、owner 与 workspace fence，贯穿原子文件发布、Core apply、精确读回及条件恢复。非活动内容写入/恢复使用 `compare_and_save_inactive_workspace` 与 `restore_inactive_workspace`；活动 profile 不再经过通用的 inactive 写入口。
- 旧 Desktop Host retry 曾在探测后丢弃临时 `CoreApplication`，无法把 owner guard 转交给长生命周期 runtime；该启动路径现 fail closed。Iced admin/rebuild 的旧 Host bootstrap API 在迁移到复用同一已绑定 Core session 前返回 typed `Unsupported`。
- Core process、Controller API/readiness、配置应用、VPN consent、TUN data plane 和真实代理流量是不同状态轴，分别用 typed enum 表达。服务启动不得隐式启动 Core；Core 启动不得隐式建立 VPN；任意单个 `running: bool` 不可授权或证明后续阶段。
- Mihomo 与 sing-box 可由同一 application contract 驱动，但 process、配置 codec、runtime API、release identity 和 capability evidence 属于各自 adapter。未真实实现并验收的操作必须返回 typed `Unsupported` 且无副作用，不能从 API 路径同名、版本字段存在、mock 或 trait 实现推断支持。
- `StartProxy` 的 Core admission 只要求 `CoreLifecycleOperation::Start`；宿主 VPN 授权、启动和停止由 typed lifecycle child 命令执行，`StopProxy` 只发送 `StopVpn` child。Core lifecycle capability 只授权 Core 进程的启动、停止与重启；`ProxyControlOperation` 专门表达 routing intent 读写，不表达宿主 VPN activation；缺少 Core lifecycle capability 时 fail closed。
- outbound 批量探测使用 typed `One`、`Collection`、有序 `Selected` 或 `All` scope，并携带预期 inventory revision、已校验的 HTTP(S) target/timeout 与 1–30 的应用层并发上限。`Collection` 展开直接的具体成员，`All` 选择具体 outbound 并排除观测到的 collection 容器；`Selected` 必须非空、ID 唯一，且每个目标都必须是当前 inventory 中的具体 outbound，集合容器、未知 ID、跨 engine ID、重复 ID 或空列表都要在任何 probe 副作用前拒绝。`Selected` 的逐项结果严格保持请求顺序。每个成员返回 `Measured`、`TimedOut`、`Unsupported` 或 `Failed`。请求 scope 或 revision 不匹配时，在 probe 调用前拒绝；adapter 可以进一步串行化请求。
- `ProfileDocument` 保留 engine 身份、原始字节、格式版本和 revision。跨引擎转换须产生目标文档与 loss report，确认前不写入。
- `EngineBackendPorts` 将纯 `ProfileDocumentCodecPort` inspection 与独立 typed native transaction 分开，并用 `EngineOperationPorts::{Unsupported, Available}` 明确 outbound/routing owner；`Unsupported` bundle 不含可 dispatch adapter。每个产品 owner 在 Core actor 创建后绑定其 `CoreScope` source 与 native transaction owner。codec 可用本身不授权 Core 配置或运行态操作。Mihomo endpoint 在获取活动 ProfileStore lease 前解析并绑定到 typed reload session；活动配置只通过 revision-fenced `PUT /configs?force=true` 验证并应用，失败或就绪读回不符时恢复精确旧 workspace。停止态候选使用所选 Mihomo binary 原生校验后再写入。sing-box 的事务目前只在 Stopped/Failed 做 native check、ProfileStore CAS、原生 JSON 文件读回与回滚，Ready/Running 保持无副作用 `Unsupported`。
- 运行时配置读取/写入使用 [scope-bound feature ports](../crates/infiltrator-ports/src/runtime_configuration.rs) 与 [`RuntimeConfigurationApplication`](../crates/infiltrator-application/src/runtime_configuration_application.rs)：写操作绑定已观察的 `CoreScope` 和 feature revision，并验证精确读回；PAC rules 与 proxy ports 是独立只读操作。共享 `RuntimeGateway` 不暴露宽配置 DTO、任意 JSON patch 或规则列表方法，Mihomo REST/wire 调用只留在 adapter 内部。
- 共享运行态使用中性快照；core 专属字段留在 adapter。`RoutingIntentPort` 在同一 typed port 上观察和应用 `RoutingIntent`，application 依据 observed `CoreScope` 与精确读/写 capability 授权，写入后要求读回一致。Mihomo adapter 独占将 `/configs` 的原生 `mode` 转换为中性意图；Desktop sing-box 当前只暴露 Core lifecycle。`EngineDefined` 的 Mihomo 读取可表达其专属状态，写入仍返回 typed `Unsupported`。通用组合层的 [`SingBoxEngineBackendProvider`](../crates/infiltrator-composition/src/engine_backend_factory.rs) 可构造 sing-box process/readiness/native JSON、typed Clash outbound/routing ports 与 profile CAS/native transaction；生产 provider 的 fake 与 SHA-locked 真实进程 conformance 均通过；Desktop 产品会话已选择该 provider，但仅开放经证据验证的 Core lifecycle，Android 产品仍未接入。sing-box 的 [`v1.14.3` 平台 archive digest 锁](../packaging/sing-box-evidence-assets.json) 的四个资产摘要已与官方 release API 匹配，Linux amd64 archive 也已本地复算；真实二进制 `check`、`run`、`/version` readiness、`/proxies` selector 观察/PUT 和 `/configs` mode-list 观察已人工运行。其适配器仅实现带 live-version/CoreScope fence 和写后读回的 Selector 选择；`/configs` 写入、三种中性 routing intent、details、delay probe 均 typed `Unsupported`。conformance 证据与范围见 [组合层说明](../crates/infiltrator-composition/README.md) 和 [sing-box API](../crates/singbox-api/README.md)、[sing-box 配置](../crates/singbox-config/README.md)、[sing-box 进程](../crates/singbox-process/README.md)、[sing-box 版本](../crates/singbox-version/README.md)。
- 资产、安装与回滚按 engine 隔离。

```text
UI → typed intent + CoreScope → application → backend adapter → core
```
